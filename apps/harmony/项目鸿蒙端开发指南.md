# Cindy 鸿蒙端开发指南

本文是 `apps/harmony` 的工程入口：接手任务、准备工具链、编译、安装或调试前阅读。功能定位见[架构与代码地图](docs/architecture.md)，专题见[文档索引](docs/README.md)。版本进度只在 `docs/version/` 维护。

## 开工与边界

先看 `git status --short` 和相关源码、测试，不覆盖已有改动。本工作区只开发和验证 `apps/harmony`；根级规则按 [AGENTS.md](../../AGENTS.md) 与[规则索引](../../docs/dev-rules/rule-index.md)查阅，不在这里复制。

- 鸿蒙视觉、组件、窗口与折叠形态以[鸿蒙界面规范](docs/harmony-ui-design.md)为设计正本。
- 用户可见行为先读 [Mobile 对齐](docs/mobile-alignment.md)，再读对应 Mobile / 共享实现，禁止猜测阈值、状态机、配对和降级路径。
- **鸿蒙不得直连模型厂商或 Agent 厂商，信息必须经电脑端获取**；不能用代理、SDK 或电脑离线回退绕过，不能下发厂商凭证。完整边界见[架构](docs/architecture.md#1-客户端边界)与 D-013。
- 页面只负责呈现和交互，Store / Service 管远程调用与状态；新增能力先从代码地图找入口。
- 签名配置、个人工具路径、设备标识和凭证不写进文档、日志或提交说明；下方无线调试端点按用户明确要求记录，其他信息仍遵守本条。现有签名不自行修改。

## 命令行工具链

本工作区使用 **HarmonyOS command-line-tools + DevEco CLI + hvigorw**，日常开发不依赖 DevEco Studio。
配套 SDK 为 API 26。环境脚本负责设置 Node、Java、SDK、OHPM、Hvigor 和 HDC；每个新终端先加载，勿沿用旧 Studio 工具路径。
以下变量由开发者在本机设置：`HARMONY_ENV_SCRIPT` 指向 command-line-tools 的 env 脚本，`HARMONY_PROJECT_DIR` 指向本 checkout 的 `apps/harmony`。它们不是仓库配置。

```sh
source "$HARMONY_ENV_SCRIPT"
cd "$HARMONY_PROJECT_DIR"
devecocli --version
devecocli device list
```

首次准备或缺少 `oh_modules` 时先读[环境准备](../../docs/dev-rules/environment-setup.md)，然后在本目录 `ohpm install`；不要用根目录 pnpm 安装替代。

### 单测与签名 HAP

先加载环境脚本，再在 `apps/harmony` 执行：

```sh
source "$HARMONY_ENV_SCRIPT"
cd "$HARMONY_PROJECT_DIR"

hvigorw test --mode module -p product=default -p module=entry@default --no-daemon
hvigorw assembleHap --mode module -p product=default -p module=entry@default -p buildMode=debug --no-daemon
```

**顺序执行**测试和构建；多人或多 Agent 共享工程时约定一个构建执行者，不并行启动多个 Hvigor。首次 MCP 检查也可能同步 OHPM、建立索引，与构建错开。遇到 `Current process status is busy` 先等已有任务结束，勿重复起任务或终止他人的构建。
环境变量错误先重新加载 env；确需停止旧 daemon 时先确认没有其他任务使用它，再 `hvigorw --stop-daemon`。

| 内容 | 相对 `apps/harmony` 的位置 |
| --- | --- |
| 签名安装包 | `entry/build/default/outputs/default/entry-default-signed.hap` |
| 构建日志 | `.hvigor/outputs/build-logs/build.log` |
| 本地单测聚合入口 | `entry/src/test/List.test.ets` |
| 单测 HTML 报告 | `entry/.test/default/outputs/test/reports/index.html` |
| 系统能力探针 | `entry/src/ohosTest/ets/test/SystemProbe.test.ets` |

`ohosTest` 依赖设备系统 API，探针占位地址 / token 未配置时不能算日常验证通过；运行须记录设备范围。
`.hvigor/`、`oh_modules/`、`entry/build/`、`entry/.test/`、`.idea/` 均非源码，不提交生成内容。
原生中转库和共享桥接产物的生成命令见[中转专题](docs/self-hosted-relay-plan.md)。

### 官方资料、Skill 与 MCP

```sh
devecocli docs catalog
devecocli docs search ArkUI 状态管理 --limit 10
devecocli docs search Repeat --catalog harmonyos-references --limit 10
devecocli docs read '<documentId>'
devecocli skills list --long
devecocli skills find '<keyword>'
```

基础 Skill 可用 `devecocli init --skill --path "$HARMONY_SKILL_DIR" --force` 安装到本机 Agent 的 Skill 目录；专项用 `devecocli skills add --skill <name> --path "$HARMONY_SKILL_DIR" --force`。
按任务选 `deveco-cli`、`hmos-arkui-develop-skill`、`hmos-arkts-knowledge-retriever`、`hmos-arkts-syntax-checker`、`hmos-local-test` 或 `hmos-multidevice-scenario-entry`。安装后重启会话；支持的 Pi 会话可 `/reload`、`/skill:<name>`。Skill 不替代仓库行为与签名约束，不照搬 `run --uninstall`。

DevEco MCP 是 stdio 服务：在本工程运行 `PROJECT_PATH="$PWD" devecocli serve mcp`。CLI 支持的 Agent 可用 `devecocli init --mcp --agent codex,claude-code --project "$PWD" --force` 生成本地配置，重启会话后使用 `check`，文件参数相对工程根。生成的 `.codex/config.toml` / `.mcp.json` 含本机路径，不提交。
Cindy Pi 无通用 stdio MCP；“外部工具”仅接远程 HTTP / SSE，不能填写该命令，也不另起常驻 HTTP 转接进程。Pi 用 CLI / Skill 检查；需要 MCP `check` 时用支持的会话。单文件检查不代替单测与完整 HAP 构建。

## 常见编译错误

| 报错来源 | 改法 |
| --- | --- |
| 构造函数参数属性 | ArkTS 不支持 `constructor(private value: T)`；单独声明成员，在构造函数赋值 |
| 组件成员冲突 | 成员不能与通用属性方法同名，如 `size`、`width`、`height`、`tabIndex`；改成业务含义名称 |
| `throw` 类型 | 必须抛 `Error`；捕获值不是 Error 时转换为 `new Error(...)`，不能原样抛普通对象或字符串 |
| `sys.symbol` 不存在 | 使用前在当前 SDK 的 `ets-loader/sysResource.js` 查资源名，不凭其他平台或旧 SDK 猜 |
| SDK / Java / Node 环境异常 | 先加载当前 command-line-tools env；确认未复用旧 daemon 的环境 |

## 选择目标、安装与启动

先用 `devecocli` 的设备 / 模拟器入口启动或选择目标，并通过 `hdc list targets -v` 确认 **Connected**。
默认选模拟器；同时有模拟器和 USB 真机时必须明确选模拟器，未经用户明确要求不操作真机。具体任务若已指定真机或不尝试模拟器，遵循该选择，不沿用其他任务的设备偏好。
`HARMONY_TARGET_ID` 由本次 Connected 目标列表填写；用户指定的无线手机端点见下节，不据此自动操作其他设备。

```sh
hdc list targets -v
export HARMONY_SIGNED_HAP="$PWD/entry/build/default/outputs/default/entry-default-signed.hap"
# 先确认文件存在、目标正确，才执行下面三条命令。
hdc -t "$HARMONY_TARGET_ID" install -r "$HARMONY_SIGNED_HAP"
hdc -t "$HARMONY_TARGET_ID" shell aa force-stop com.eno.cindy
hdc -t "$HARMONY_TARGET_ID" shell aa start -a EntryAbility -b com.eno.cindy
```

**签名与安装红线：**

- 只能使用现有签名配置生成的 `entry-default-signed.hap`，禁止用 unsigned HAP 覆盖已有应用。
- 禁止为了绕过签名而卸载应用、清理数据或重置模拟器。
- 签名材料不可用、signed HAP 不存在或 `install -r` 签名不一致时立即停止，交给用户处理；必要时由用户在 DevEco Studio 中配置正确签名。不得自行修改 `signingConfigs.default`，不得打印或复制签名字段。
- 构建成功不等于安装成功，安装成功不等于功能验收通过。旧画面先核对构建结果、包、目标与覆盖安装回执，不只看时间戳（可能命中缓存）。

### Wi‑Fi 调试与无线覆盖安装

用户指定的手机为 **HUAWEI Pura X Max 典藏版（API 26）**。按用户要求记录的无线调试地址：

- IP：`192.168.31.66`
- 端口：`42421`
- HDC 连接地址：`192.168.31.66:42421`
- 最近成功覆盖安装：2026-11-28。

这是本次已验证的端点，不是固定设备身份。重新开启无线调试、重启或更换网络后地址 / 端口可能变化；连接失败或手机页面显示不同值时，以手机「无线调试」页面为准，不扫描其他设备。电脑和手机须网络互通，手机保持解锁；必要时停留在无线调试页面，并由用户处理手机上的授权提示。

先加载 command-line-tools 环境，全部命令在 `apps/harmony` 内执行。已知手机端点时直接用同一套 HDC 完成连接、安装和启动：

```sh
source "$HARMONY_ENV_SCRIPT"
cd "$HARMONY_PROJECT_DIR"
export HARMONY_TARGET_ID='192.168.31.66:42421'
export HARMONY_SIGNED_HAP="$PWD/entry/build/default/outputs/default/entry-default-signed.hap"

hdc tconn "$HARMONY_TARGET_ID"
hdc list targets -v
# 必须看到目标地址为 Connected；签名包不存在、仍在生成或任一步失败时停止。
unzip -t "$HARMONY_SIGNED_HAP"
hdc -t "$HARMONY_TARGET_ID" install -r "$HARMONY_SIGNED_HAP"
# 必须收到 install bundle successfully 后再启动；仅有 AppMod finish 不算成功。
hdc -t "$HARMONY_TARGET_ID" shell aa start -a EntryAbility -b com.eno.cindy
```

- 多人并行开发时，安装已有最新 signed HAP，不另起构建，不改代码、签名或他人的工作区状态。确认包已生成完毕且检查 / 传输期间没有被重写；大小、修改时间或摘要变化时重新确认产物。只看版本号不能区分同版本的新包。
- 传包时曾出现 Wi‑Fi 断连、CLI 退出却无明确安装回执。先 `hdc list targets -v` 核对；列表为空时用相同地址 `hdc tconn` 重连，再执行上述 HDC 覆盖安装。CLI 无输出或仅有 `Connect OK` 均不等于安装成功。
- 安装以 `install bundle successfully` 回执为准，启动以 `start ability successfully` 为准。必要时用 `hdc -t "$HARMONY_TARGET_ID" shell bm dump -n com.eno.cindy` 核对包版本及 `updateTime`，只提取所需字段，不将完整设备信息写入仓库。
- 签名错误仍按上面的红线停止交给用户处理；不换 unsigned 包，不卸载、不清数据、不重置设备。

| 现象 | 优先排查 |
| --- | --- |
| 无设备 | 模拟器是否启动、目标是否 Connected、HDC 是否来自当前工具链 |
| 点击无变化 / 上传状态滞留 | Store notify、`@State` 对象 / 数组 / Map 引用替换、busy / 遮挡；`ForEach` key 是否表达必要 revision |
| Tab 或列表闪黑 | 条件分支销毁重建、不必要的 `stateEffect`、节点身份与方向动画 |
| 远程操作无结果 | resolving 状态、invoke envelope 解包与业务错误可见性 |
| 历史重复或断层 | 窗口覆盖、稳定 key、push 合并、gap healing 与补拉 |
| 与 Mobile 不一致 | 返回对应源码核对行为，勿继续在 ArkUI 上叠补丁 |

对象状态更新优先替换引用；`ForEach` key 稳定且只在必要的代次变化时重建，禁用随机 key。列表 / Tab 切换保留页面身份；滑杆等不需要底色的控件关闭多余 `stateEffect`，保留无障碍文字。动画优先 transform / opacity，合理设置 `ExpectedFrameRateRange` 并尊重减弱动态效果。

## 验证与交付

按[验证清单](docs/verification-plan.md)选择与改动匹配的单测、signed HAP 和交互验收。解析与状态机测试归 `src/test`，系统网络、URI 和生命周期归设备测试；新增测试先读根工程规范的价值门槛。
UI 同时检查 Light / Dark、窄屏 / 展开态、键盘 / 返回 / 弹层、60 / 120Hz 和减弱动态效果。颜色用 base / dark 同名 token，远程失败必须可见。
只在 Harmony 内验证，不运行根或其他客户端测试；文档整理无需构建。交付前审阅 `git diff --check -- apps/harmony` 与完整 diff，如实列已验证、未验证、设备范围和剩余风险。
Git、DCO 与外部写操作以[开发工作流](../../docs/dev-rules/development-workflow.md)为准；本指南不授权提交、推送或安装到未选定设备。

## Fork 分支的提交与推送

用户明确授权提交 / 推送后使用本节；先核对当前分支与 `origin` 是目标 fork，逐项暂存本次文件，保留本机签名配置等已有改动。提交必须 `git commit -s`，不自动更改 Git 身份。

本工作区已验证可通过既有 SSH 授权推送。`origin` 保持 HTTPS 地址时，非交互终端可能报 `could not read Username for 'https://github.com': Device not configured`；下次优先使用下面的临时 SSH 推送方式，不先重复尝试缺少凭据的 HTTPS，也不假设已安装 `gh`。

以下从 `apps/harmony` 执行。`HARMONY_FORK_SSH_URL` 填入与 `origin` **同一 fork** 的 SSH 地址（`git@github.com:<fork-owner>/<fork-repo>.git`），不填写私钥路径或凭据；分支使用当前任务分支，不硬编码版本号。

```sh
git status --short --branch
git remote get-url origin
HARMONY_PUSH_BRANCH="$(git branch --show-current)"
# 确认分支非空且为本次目标分支；逐项 git add -- 文件路径，再检查暂存内容。
git diff --cached --stat
git diff --cached --check
git commit -s -m 'docs(harmony): 更新开发文档'

# 先确认既有 SSH 授权可读取同一 fork；无授权或主机密钥未确认时停止。
GIT_SSH_COMMAND='ssh -o BatchMode=yes -o StrictHostKeyChecking=yes -o ConnectTimeout=10' \
  git ls-remote "$HARMONY_FORK_SSH_URL" HEAD

# 只对本次命令覆盖 pushurl，保留 origin 的持久配置和跟踪关系。
GIT_SSH_COMMAND='ssh -o BatchMode=yes -o StrictHostKeyChecking=yes -o ConnectTimeout=10' \
  git -c remote.origin.pushurl="$HARMONY_FORK_SSH_URL" \
  push -u origin "HEAD:refs/heads/$HARMONY_PUSH_BRANCH"

git status --short --branch
```

检查每条命令的退出码，读取探测失败不继续推送；探测成功只证明可读，最终以 push 回执的仓库、分支及成功状态为准。首次推送当前分支会一并发布其尚未推送的祖先提交，先审阅提交范围。不要将 SSH 地址指向 `upstream`，不要用强推解决远端分歧，也不为凭据问题修改签名配置、打印令牌或关闭 SSH 主机密钥校验。
