# Cindy 鸿蒙端开发指南

> 给后续开发者和 AI 的快速入口。本文只介绍长期有效的工程结构、开发方法和验证命令，不记录功能进度。

## 1. 先了解项目

- 工程目录：`apps/harmony`，它本身就是一个独立的 DevEco Studio 工程。
- 技术栈：HarmonyOS 6.1 / API 24+、Stage 模型、ArkTS、ArkUI。
- 应用定位：鸿蒙端是桌面 Cindy 的远程控制客户端；Agent、任务数据、工作目录和工具仍运行在桌面端。
- 通信方式：通过认证 API 和 Device Link（HTTP + WebSocket）连接桌面 Cindy。
- 工程边界：默认只修改 `apps/harmony`。不要在鸿蒙端运行 Agent，不要新增 Harmony 专用协议，也不要直接照搬 React Native 代码。
- 行为准绳：用户可见行为以 `apps/mobile` 和共享逻辑为事实源，ArkUI 只负责平台适配和原生呈现。

## 2. AI 接手时的最短流程

1. 在仓库根目录执行 `git status --short --branch`，保护已有改动，不回退无关文件。
2. 先读根目录 `AGENTS.md`，再按任务类型读下表中的资料。
3. 先查 Mobile / 共享实现，再决定 ArkTS 行为；不要凭截图猜状态机、阈值或协议字段。
4. 修改范围尽量限制在 `apps/harmony`，沿用已有 Store、Service、资源 token 和 ArkUI 写法。
5. 顺序执行单元测试和 HAP 构建，然后使用**带签名 HAP** 覆盖安装到模拟器，做真实交互和截图检查。
6. 最后检查 `git diff --check -- apps/harmony` 和完整 diff，如实记录已验证与未验证项。

## 4. 代码地图

```text
apps/harmony/
├── AppScope/                         # bundle、版本和应用级资源
├── build-profile.json5              # 产品、SDK、构建模式、签名配置
├── entry/
│   ├── build-profile.json5           # entry 模块构建配置
│   └── src/main/
│       ├── module.json5              # Ability、权限、页面和设备类型
│       ├── ets/
│       │   ├── entryability/         # 应用生命周期入口
│       │   ├── pages/                # 登录、首页、任务列表、任务详情、设置
│       │   ├── core/                 # Auth、Device Link、任务、消息、附件、交互、存储
│       │   ├── network/              # Harmony HTTP / WebSocket 适配
│       │   └── AppConfig.ets         # 平台标识、版本和服务端地址
│       └── resources/
│           ├── base/                 # Light 默认资源、字符串、尺寸、媒体
│           └── dark/                 # Dark 资源覆盖
└── docs/                             # Harmony 专项设计、架构和验证资料
```

关键入口：

- `EntryAbility.ets`：窗口和前后台生命周期。
- `pages/Index.ets`：初始化服务、恢复登录态并路由。
- `core/AppServices.ets`：组装 Auth、Device Link 和各业务 Store，分发远程事件。
- `pages/TaskPage.ets`：任务详情页和 ArkUI 消息/Composer 交互。
- `core/messages/MessageStore.ets`：历史、订阅、流式合并和发送。
- `core/messages/MessageRender.ets`：消息归一化和渲染模型。

页面不要直接创建 WebSocket 或拼 Device Link envelope；跨页面状态和远程行为放入对应 Store / Service。

## 5. 开发环境

推荐直接用 DevEco Studio 打开 `apps/harmony`。当前工程使用 DevEco 自带的 SDK、JBR、Hvigor 和 HDC；首次打开时等待工程同步完成。

命令行开发可先在终端设置：

```bash
cd /path/to/cindy-harmony/apps/harmony

export DEVECO_HOME=/Applications/DevEco-Studio.app/Contents
export DEVECO_SDK_HOME="$DEVECO_HOME/sdk"
export JAVA_HOME="$DEVECO_HOME/jbr/Contents/Home"
export HVIGOR="$DEVECO_HOME/tools/hvigor/bin/hvigorw"
export HDC="$DEVECO_HOME/sdk/default/openharmony/toolchains/hdc"
```

若 DevEco 安装位置不同，替换 `DEVECO_HOME`。目标和兼容 SDK 由 `build-profile.json5` 固定为 `6.1.1(24)`。

## 6. 测试和编译 HAP

测试与构建必须顺序执行，同一个 Harmony 工程不要并行启动多个 Hvigor 任务。

```bash
# ArkTS 本地单元测试
"$HVIGOR" test \
  --mode module \
  -p product=default \
  -p module=entry@default

# 编译 debug HAP
"$HVIGOR" assembleHap \
  --mode module \
  -p product=default \
  -p module=entry@default \
  -p buildMode=debug
```

当前工程的 `build-profile.json5` 已配置 `signingConfigs.default`，构建成功后会同时看到 signed / unsigned 产物。设备上已有应用时，只能使用 signed 产物：

```text
entry/build/default/outputs/default/entry-default-signed.hap
```

不要使用 `entry-default-unsigned.hap` 覆盖已有应用。unsigned HAP 可能触发签名不一致；卸载应用、清理应用数据或重置模拟器会丢失登录态和本地数据。若签名材料不可读、signed HAP 不存在，或 `install -r` 报签名不一致，停止操作并交给用户在 DevEco Studio 中处理，不要自行修改签名配置或卸载应用。

## 7. 安装并启动模拟器

先在 DevEco Studio 的 Device Manager 启动 HarmonyOS 手机模拟器，再查看目标：

```bash
"$HDC" list targets
```

当前常见模拟器目标是 `127.0.0.1:5555`。若输出不同，以实际目标替换下面的 `TARGET`：

```bash
export TARGET=127.0.0.1:5555
export HAP="$PWD/entry/build/default/outputs/default/entry-default-signed.hap"

# 只允许使用 signed HAP 覆盖安装，保留正常的升级安装语义；禁止 uninstall / 清数据
"$HDC" -t "$TARGET" install -r "$HAP"

# 停止旧进程并启动主 Ability
"$HDC" -t "$TARGET" shell aa force-stop com.eno.cindy
"$HDC" -t "$TARGET" shell aa start -a EntryAbility -b com.eno.cindy
```

应用标识来自 `AppScope/app.json5`：bundle 为 `com.eno.cindy`，主入口为 `EntryAbility`。

## 8. 查看效果和排查问题

最直接的方式是在模拟器中操作真实页面。每次 UI 改动至少检查 Light / Dark、键盘弹出、返回、滚动和窄屏布局；会话页优先使用手机纵向或折叠态检查。

截取当前模拟器画面：

```bash
"$HDC" -t "$TARGET" shell snapshot_display \
  -f /data/local/tmp/cindy-harmony.jpeg
"$HDC" -t "$TARGET" file recv \
  /data/local/tmp/cindy-harmony.jpeg \
  /tmp/cindy-harmony.jpeg
```

查看运行日志：

```bash
"$HDC" -t "$TARGET" hilog | rg 'CindyHarmony|CindyApp'
```

常见问题：

- `Current process status is busy`：另一个 Hvigor 任务仍在运行；等待结束后顺序重试，必要时执行 `"$HVIGOR" --stop-daemon`。
- `list targets` 为空：模拟器尚未启动，或 HDC 未连接；先在 Device Manager 启动设备。
- 安装后仍是旧画面：确认使用的是最新 signed HAP，再执行覆盖安装、force-stop 和 start；不要为了绕过签名错误卸载应用。
- `install sign info inconsistent`：通常是 HAP 签名与设备上的旧应用不一致；停止操作，让用户在 DevEco Studio 选择正确签名，不要卸载应用或清除数据。
- 只有编译警告：先判断是否为已有警告；新增代码不得引入新的高风险警告或用忽略规则掩盖问题。
- 页面有数据但行为不一致：回到 Mobile / 共享源实现核对协议字段、状态机和降级路径。

## 9. 最小交付门槛

- 变更只触及任务需要的模块，未覆盖用户已有修改。
- 用户可见行为已与对应 Mobile / 共享实现核对。
- Light 和 Dark 都使用语义颜色资源，不在页面散落硬编码主题色。
- 相关单元测试通过，`assembleHap` 通过并生成 signed HAP。
- HAP 已安装到模拟器，核心交互实际操作过；UI 改动有截图检查。
- `git diff --check -- apps/harmony` 通过，并已人工审查完整 diff。
- 未执行的相关验证、剩余风险和环境限制在交付说明中明确写出。
