# Harmony 一期产品范围

> 状态：Draft
>
> 本文是 Harmony 客户端一期的范围基线。它定义“核心远程控制能力必须完整”，不追求第一期覆盖所有外围客户端能力。

## 1. 产品定位

Harmony 端是 Cindy 的原生远程控制客户端：

- 用户在鸿蒙设备上登录 Cindy 账号。
- 鸿蒙端发现可控的桌面 Cindy。
- Agent、任务数据、工作目录、SQLite、CLI、MCP 和插件继续运行在桌面端。
- Harmony 端通过 Device Link 查看任务、读取对话消息、发送输入并处理用户确认。

用户可见术语遵循仓库规则：

- 可单独打开、删除或重命名的 `session` 称为“任务”。
- 任务内人与 AI 的交流过程称为“对话”。
- 对话中的单条往来称为“消息”。

## 2. 一期必须实现

### 2.1 认证和设备

- 一种稳定的登录方式（优先验证码登录；OAuth 需要时再接入系统浏览器回调）。
- Token 安全存储、刷新、登出和账号切换清理。
- 设备发现、在线/离线状态、远程控制权限状态。
- Device Link 连接、心跳、重连、撤权和错误状态。

### 2.2 任务和对话

- 任务列表。
- 打开已有任务。
- 历史消息完整加载、向上翻页和按窗口加载。
- 重连后从桌面端补齐缺失消息。
- 流式消息增量展示和稳定排序。
- Thinking、Tool、Todo、Work Group、系统消息、错误消息和交互等待状态。
- 基础 Markdown：段落、标题、列表、引用、表格、代码、链接和图片。
- 消息复制、代码复制、图片/媒体预览、文件引用入口。
- Fork、Rewind 等核心消息动作。

### 2.3 输入和附件

- 多行文本输入。
- 发送和停止。
- 发送中、失败和重试状态。
- 图片选择。
- 多图附件。
- 图片压缩、上传进度、失败重试。
- 图片发送后在历史消息中恢复和预览。
- 任务运行期间待发送消息不丢失，具备基本队列语义。

### 2.4 AI 交互确认

以下三类交互一期完整支持：

- Permission：允许一次、始终允许、拒绝。
- Ask User：单选、多选、自定义输入、跳过、多步骤和草稿恢复。
- Plan Review：查看计划、编辑、批准、反馈、提交冻结和重复提交保护。

`issue_confirm` 延续现有移动端策略：一期识别协议并明确提示回桌面处理，不在 Harmony 端实现 GitHub Issue 编辑和提交表单。若要改变该策略，需要单独记录产品决策。

## 3. 一期页面

```text
登录页
首页：设备和任务列表
任务详情：对话消息流、输入区和任务动作
Permission / Ask User / Plan Review 页面或弹层
设置页：账号、设备、登出
```

## 4. 一期不做

以下能力不影响核心 AI 交互闭环，暂不纳入：

- 语音输入。
- 系统推送和后台常驻 WebSocket。
- 微信、Google、Apple 等额外登录方式。
- 视频和音频上传。
- 完整文件树和文件编辑器。
- 自动化管理。
- Orca 多 Agent 编排。
- 插件系统。
- SSH 远程工作区。
- 完整模型供应商和高级运行参数设置。
- 商店分发、统计和热更新。

一期不上传视频和音频，不代表可以丢弃历史中的视频、音频和文件引用；消息数据模型必须保留这些内容，并提供可识别的预览或查看入口。

## 5. 范围原则

1. 核心消息和交互不做半套，第一版就建立完整数据模型。
2. 桌面端是任务和消息的权威来源，手机端不另造一套历史事实。
3. 不为了复用 React Native 页面而牺牲 ArkUI 原生结构。
4. 不新增 Harmony 专用远程协议；优先兼容当前 Device Link。
5. UI 只使用 ArkUI 原生组件；复杂 Markdown 内容可局部使用 ArkWeb 承载。
6. Light 和 Dark 两种模式同时实现。
7. 现有 Mobile 资源可以复用，但不复制 Mobile 的页面层级。
