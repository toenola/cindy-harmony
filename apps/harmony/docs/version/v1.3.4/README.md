## Review 修正（2026-10-27）

整体 review 后修正四处问题，均限于 `apps/harmony`：

| # | 问题 | 修正 |
|---|---|---|
| 1 | 常驻任务被隐藏时不释放排队消息的编辑锁，该消息在查看其他任务期间无法派发（F2 引入的回归，原先离页会释放） | 隐藏时调用 `cancelQueueEdit()`：释放锁并恢复编辑前的草稿，随后照常保存草稿 |
| 2 | 隐藏的运行中任务仍保留 500ms 的工作计时器，后台持续重绘 | 隐藏时 `stopWorkClock()`；恢复时 `refreshItems` 按流式状态重新启动 |
| 3 | TaskStore 直接移除已删除任务，「找不到」被一律保留，已删除任务一直常驻 | 判定移入 `residentPaneSurvives`：曾见过且该电脑列表仍有数据才视为删除；当前选中的任务待选择切换后再释放，列表为空时保留 |
| 4 | 窗口避让区读取失败时安全区恒为 0，任何设备都进不了双栏 | `effectiveTaskSafeWindow`：读取失败退回页面尺寸，读取中仍按 0；高度不与页面高度取小，输入法弹出时不收起双栏 |

验证：Local Test 471 项通过（Failure 0、Error 0），新增 3、4 的回归用例在修正前会失败；
`assembleHap` 通过并生成 `entry-default-signed.hap`。1、2 属于界面生命周期，需在设备上验证：
编辑排队消息时切到其他任务，原任务的该消息能继续派发；隐藏运行中的任务不再持续重绘。
尚未进行任何设备验收与安装。

## 第二轮 review 修正（2026-10-27）

| # | 问题 | 修正 |
|---|---|---|
| 1 | 任务增量 patch 会清空未携带字段：`lastActivityAt`（最近活动退回旧时间），以及既有的 `agentDeviceId`（v1.3.2 B2 的位置标签与换模型防护随之失效）、运行时档位、`clearedAt`、轮次时间 | `TaskStore.mergeSession` 直接以旧任务的完整记录为底合并，`sessionToRecord` 补齐 `parseSession` 读取的全部字段，与 Mobile `{...prev, ...patch}` 语义一致 |
| 2 | 常驻任务的消息定位参数不更新：ForEach 按任务 key 复用实例，替换同 key 的 pane 对象不会重新执行子组件构建，搜索结果 / 深链跳不到目标消息 | 定位目标与递增的 `selectedMessageRevision` 从父级 `@State` 传入；同一条消息再次选择也会重新定位 |
| 3 | 切换任务时 Pi 分支切换标记不复位，返回后分支面板被锁住；同类按代次清理的 `sessionTreeLoading`、`composerPaletteLoading`、`tailBannerBusy` 也会卡住 | 隐藏时一并复位，并清除账户用量刷新定时器 |
| 4 | 多个常驻任务的输入框共用 `task-composer-input`，焦点请求可能命中隐藏任务 | 按账号代次、设备与任务生成唯一 ID（`taskComposerInputId`），三处 `requestFocus` 与 Composer 统一使用 |

验证：Local Test 473 项通过；第 1 项的回归用例在旧 `TaskStore` 上失败、修正后通过；`assembleHap` 通过。
第 2、3 项属于界面生命周期，需在设备上验证：常驻任务中点搜索结果能跳到目标消息；
分支切换途中切走再切回，分支面板可关闭、可再次切换。尚未进行设备验收与安装。
