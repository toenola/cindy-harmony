上游规则：窗口宽 ≥600，且安全区宽 ≥760、高 ≥480 才显示双栏。

| 折叠横屏 | 672×459 | 单栏（宽 <760） | 单栏（折叠态） | — |
| 展开竖屏 | 664×939 | 单栏（宽 <760） | 单栏（非横屏） | — |
| 展开横屏 | 939×664 | 双栏 | 双栏 | 列表宽度规则改变（见下） |
| 展开左右分屏 | 388 / 465 / 543 ×664 | 单栏 | 单栏 | — |
| 展开上下分屏 | 664×445 / 664×593 / 664×296 | 单栏 | **双栏**（宽 ≥640 且宽 > 高） | **改为单栏** |

- 展开横屏的安全区高 = 664 − 状态栏 − 导航条，仍远高于 480；安全区宽需扣除横屏时的挖孔避让，
  以实机读数为准，预计仍 ≥760。
- 列表宽度：上游 240 – min(420, 宽 − 400)，默认 min(320, 宽 × 34%)。939 宽时默认 319，
  可拖动范围 240 – 420（现为 25% – 60%，即约 300 – 563）。
- 当前列表下限 300 是为容纳设备下拉、四个头部按钮和底部导航（`TaskSplitLayout.ets` 注释）。
  F1 需在 240 宽下逐项检查列表头部；装不下时保留 300 下限，作为有意差异写入 decision-log，
  不为了对齐数字而让控件重叠。

## 4. 实现交接要点

开发前仍须按 `docs/mobile-alignment.md` 读一遍对应 Mobile / 共享源码，本节只作索引。

### B2 富组件序号缺口

- 对齐 `packages/maker-shared/src/richAnswer.ts`：`seq > this.seq + 1` 时
  `issues += Math.min(seq - this.seq - 1, MAX_NODES)`，然后继续应用本行；`seq <= this.seq` 仍按重放静默跳过。
- Harmony 现状 `RichAnswer.ets:227` 抛 `gap` 且不推进 `this.seq`，导致缺口后所有行都被丢弃。
- 单测：中间一行 JSON 损坏，后续 create / patch 仍生效且 `issues > 0`。

### B1 富组件按钮 send

- 移植 `richSendText(node, values)`：仅 button / form；`props.send` 求值为字符串，trim 后非空且 ≤16000 字符才有效。
  `send` 与 `set` 同时出现时以 Host 指南为准（指南要求二者不并用），实现时照共享层行为处理。
- 移植 `RichSubmissionController`：状态 idle / sending / sent / failed；
  已发送记录写入现有 `RichInteractionMemory`，key 为 `${stateKey}:sent:${nodeId}`，同一文本已提交则不可重复；
  失败只记内存（最多 256 条），保留控件值供重试。
- 按钮可用条件对齐 Mobile：回答已完成、文档无 issues、当前界面允许发送、文本有效，且状态不是 sending / sent。
  按钮旁显示将要发送的文本。
- 发送通道：Mobile 用 `send({ independentText })`——独立于 Composer，**不清空草稿、不带附件、不解析斜杠命令、
  不触发推荐 / 语音状态**，任务运行中按正常规则入队。Harmony 在 `InputQueueStore` / `MessageStore` 的正常发送入口上
  提供同等的独立发送，不复用 Composer 的草稿清理路径。
- 只读场景（分享预览、搜索结果、历史快照等）不提供发送。
- 文案五语：发送消息 / 正在发送… / 已提交 / 消息未提交，已保留填写内容（参考 Mobile `message.json` 同名 key）。

### B3 commentary 不并入答复

- 对齐 `messageRender.ts` 的 `canPrependToAnswer`：`agentMeta.assistantPhase === 'commentary'` 的消息
  不能作为答复段向前扩展的一员。
- Harmony `MessageRender.ets` 中向前回溯 `answerStart` 的两处（约 2403、2438 行）都要加该判定；
  保持 D-012 中已定的工作组 key 规则不变。

### B4 小项

- **lastActivityAt**：`TaskModels.parseSession` 读取该字段；`TaskListSnapshotStore`、`TaskListPresentation`、
  `TaskSearchStore` 的最近时间统一为 `lastActivityAt → userSendAt → updatedAt → createdAt`
  （共享 `getSessionListActivityAt`）。快照写入时一并保存，旧快照缺字段按原顺序回退。
- **项目别名**：只读 `local-db:project-aliases:list`（无参数，后台优先级），回包为
  `[{ projectKey: 'local:<path>', alias }]`，只接受 `local:` 前缀，同一路径取第一条（Host 新的在前）；
  键规则照 `projectAliases.ts` 的 `remoteProjectAliasKey`，分组显示名照 `projectAliasSync.ts`
  `resolveProjectAliasForSessions`（按分组成员解析，不受搜索 / 筛选影响）。
  订阅推送 `local-db:project-aliases:changed`（无 sessionId）后重读；订阅 ACK 后再读一次，避免漏掉期间的改名；
  回前台重读。旧 Host `CHANNEL_NOT_ALLOWED` 视为无别名，其它失败 2 秒后重试，最多 3 次，失败期间保留上次结果。
  别名只用于显示，不改分组、路径与项目顺序；Harmony 端不提供改名写入。
- **电脑名称**：照 `deviceList.ts` 的 `deviceDisplayName`：设备 ID 不得作为显示名；同名（忽略大小写）电脑按
  设备 ID 排序后追加 `(1)`、`(2)`；未命名电脑用本地化的「未命名电脑」。设备列表、任务来源、新建页设备选择统一使用。
- **转发请求**：照 `forwardedRequestDisplay.ts` 的 `forwardedRequestDisplayText`，只在显示层解码完整信封
  （六种方言，含后台任务前置两行），复制原文、引用与重发仍用原始内容。

### F1 双栏按窗口尺寸

- `isWideTaskLayout` 改为：宽 ≥600 且安全区宽 ≥760、安全区高 ≥480；去掉宽 > 高与 foldStatus 条件，
  `TaskListPage` / `TaskPage` 不再需要监听 `foldStatusChange`（只依赖窗口尺寸变化）。
- 安全区：当前 viewport 取页面 `onAreaChange`。需确认该区域是否已扣除状态栏、导航条与挖孔；
  若页面为沉浸式布局，改用窗口避让区（系统栏、导航指示条、`TYPE_CUTOUT`）计算安全区，不重复扣除。
- 列表宽度改为第 2 节的绝对宽度规则；当前比例只存在页面内存，未持久化，无需迁移。
  拖动按宽度增量计算并夹到新范围。
- `taskDetailKeyboardInset` 等依赖 `isWideTaskLayout` 的调用一并改用新签名，键盘只抬高详情栏的规则不变。
- 更新 `TaskSplitLayout.ets` 头部注释与开发指南中相关描述。

### F2 双栏常驻最近 3 个任务

现状：`TaskListPage.detailPane` 以 `ForEach([selectedTaskInstanceKey()])` 只挂一个 `TaskPageContent`，
每次切换都销毁重建。`MessageStore` 本身已按会话缓存（最多 12 个会话、1600 行），所以 F2 解决的是
界面重建、重新排版和阅读位置恢复，而不是数据重新拉取。

对齐 Mobile `RecentMessageHistories`（`docs/design-evidence/iphone-duo-adaptation.md`「横屏侧栏切换保留最近消息列表」）：

- 双栏下最多保留 3 个 `TaskPageContent`，叠放在同一详情区域、尺寸相同；当前任务可见，其余隐藏。
  按「账号代际 + 设备 + 任务」定位实例；超过 3 个时释放最久未看的那个。
- 新增 `paneActive` 输入。隐藏实例必须：
  - 不接收触摸，不进入读屏树；
  - 暂停自动补页、贴底跟随、阅读书签修正和可见消息 / 已读回调；
  - 关闭图片查看器、正文查看器、消息操作菜单、模型 / 权限等弹层，收起键盘；
  - 不处理期间积累的「跳到最新」请求；重新激活时不重放。
- 订阅：隐藏实例是否保持 `session:<id>` 订阅需在实现前确定。建议隐藏即退订、激活时重新订阅并做一次增量补齐
  （与 Mobile 暂停订阅一致），同时把常驻的 3 个会话从 `evictInactiveSessionCaches` 中保护起来，
  避免缓存被淘汰后实例显示空列表。
- Composer 草稿按任务独立保存（现有 `ComposerDraftStore`），切换时不串任务。
- 释放时机：退出双栏、切换账号、任务被删除 / 归档。窄屏保持现有单实例路由。
- `TaskPage.ets` 已超 1.2 万行：暂停 / 恢复判定放入 `core/` 的纯函数或小型控制器并单测，页面只做接线。

## 6. Review 关注点

- B1：发送是否可能清掉 Composer 草稿或带上附件；只读场景是否还有可点的发送；同一文本能否被重复提交。
- B2：缺口计数是否可能超出节点上限；重放行是否被误计为问题。
- B4：别名是否泄漏到分组键或项目顺序；旧 Host 是否会反复报错重试。
- F1：是否还有代码路径依赖 foldStatus 或横竖屏判断双栏；安全区是否重复扣除。
- F2：隐藏实例是否仍在补页、贴底、发已读或弹出浮层；常驻会话的缓存是否会被淘汰；
  内存占用在 3 个长历史任务下是否可接受（回答「故障半径三问」）。
