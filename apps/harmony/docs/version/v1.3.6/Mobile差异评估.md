# Harmony v1.3.6 Mobile 差异评估

评估日期：2026-11-12。以 `ae7bd07215..4f3ff83522` 的最终源码为准；优先级是建议开发顺序，
不代表已复现的设备缺陷。

## 比较范围

- 本次上游相对 fork 原有头部的共同基点为 `ae7bd07215`。上游新增 2046 个提交，
  其中触及 `apps/mobile` 的非合并提交 154 个。
- Mobile 净差异 565 个文件，约 +23994 / −4730 行；包括测试、i18n、原生模块、文档与业务代码，
  文件数不能直接当成待移植功能数。
- 上游此区间没有修改 `apps/harmony`。Harmony 对照基线是 v1.3.5 的 `3517f94f21`。
- v1.3.5 的富组件容错、`projectDir` 归组、编辑最后一条消息、Codex 提问初版、Mermaid 和跨电脑模型
  已在 Harmony 实现；下面只记录这次新增的行为与仍存在的差距。

## 建议直接跟进

| 顺序 | Mobile 最终行为与源码 | Harmony 当前情况 | 建议验收结果 |
| --- | --- | --- | --- |
| 1. 异步提问连续性 | `remoteSessionStore.ts` 为每张正在编辑的异步提问保留独立快照；`InteractionPanel.tsx` 在模型撤回问题时保留答案草稿并允许作为补充消息发送；`messageNormalize.ts` 让已回答的问题只在卡片显示一次。参见 `b1337523bb`、`6a3f869107`、`21977b184c`、`fa611e2118` | `InteractionStore.ets` 收到 `maker:interaction-dismissed` 即移除请求并清草稿；`TaskPage.ets` 已支持作答中通知与答案约束，但没有撤回后的补充发送路径 | 同时编辑多张问题、模型撤回其中一张、断线丢回执、其他设备已回答时，均不丢草稿、不重复提交；已回答问题不再显示第二个用户气泡。先核对共享 `interaction.ts` 的补充文本与回执判据 |
| 2. 任务移到其他项目 | `SessionProjectMoveSheet.tsx` 通过 `TASK_MIGRATION_CHANNEL` 先读 `caps`，再执行 `move-project`；运行中禁止移动，丢回执后重新取快照而不重放写操作。参见 `7c96336eb0` 及后续修复 | Harmony 已按 `projectDir` 分组并支持新建时选项目，但没有既有任务迁移入口或 `move-project` 调用 | 菜单可将未运行任务移到另一项目或「对话」；旧 Host 不支持时给清楚提示；成功后清掉旧 `projectDir` 并刷新列表；失败保留重试能力 |
| 3. 跨电脑模型档位记忆 | `remoteAgentModelMemory.ts` 按账号、远程电脑、Agent、来源、模型分别保存 effort / Fast；没有记忆时取目标电脑目录推荐值，恢复推荐时删除记忆。参见 `7b73106747` | `NewSessionPage.ets` 与 `TaskPage.ets` 已按远程电脑区分模型行，但 effort / Fast 只在页面 `@State Map` 中记忆，页面销毁后丢失 | 切换任务、重新进页面及冷启动后仍保留对应电脑的档位；不同账号、电脑及同名来源不串用；远程能力撤回时回退到当前目录推荐值 |
| 4. 可远程确认的 Issue 卡 | `InteractionPanel.tsx` 对 `remoteConfirmSupported === true` 且非共享访客显示 `IssueConfirmCard.tsx`，支持本地草稿和明确提交；其他情况保持只读。参见 `a4e2865432` | `TaskPage.ets` 对所有 `issue_confirm` 仍显示「回电脑处理」状态卡 | 只为电脑明确声明可远程确认的请求提供确认入口；共享访客与旧 Host 保持只读；提交失败时保留草稿，避免重复决定 |

异步提问属于本版最先处理的兼容缺口：Host 已经会撤回请求，Harmony 当前直接清除用户已输入的答案。
项目迁移和 Issue 卡是新增能力；跨电脑模型档位记忆是 v1.3.5 已交付能力的连续性补齐。

## 小项与仅验证

| 主题 | 本次 Mobile 变化 | Harmony 判断 |
| --- | --- | --- |
| 提问卡布局 | 自由输入不自动聚焦，先让题目可读；输入框可多行，底部随键盘留空间（`90eb9bde93`） | 对照 Harmony 原生输入框在键盘弹出时是否遮住题目；这是布局验收，不照搬 RN 手势代码 |
| 模型账号配额 | `useMobileModelQuotas.ts` 统一多账号额度，选择器按来源显示剩余额度与重置，避免把某账号余量误投到同名模型（`afd07301d2`、`02a1c192b9`） | Harmony 目前没有对应的账号配额选择器；建议另列功能增强。开发前先核对被控端目录与用量数据契约，不把任务上下文 tokens 当账号额度 |
| 消息来源 | Mobile 保留附件单独发送时的 IM 来源抬头，补 iMessage 来源及气泡归属（`bf3b6f0fd2`、`a664d340a8`） | Harmony 已有 `MessageSourcePresentation.ets` 的设备、插件和任务来源标签；需用真实来源样本验证附件消息与 IM 标签，确认具体缺口再改 |
| 文件预览错误 | `filePreviewFailure.ts` 把远程媒体错误码翻为用户可读提示（`f86cb664c5`） | 核对 Harmony 预览与图片查看器是否泄露 `[MEDIA_SOURCE_MISSING]` 等协议码；若有，复用同一错误分类语义 |
| 搜索结果标签 | 搜索结果标题旁显示任务标签（`0c16c81895`） | Harmony 搜索结果目前未发现标签展示；低风险的可选体验增强 |
| 归档撤销提示 | Mobile 把撤销归档提示移至输入框上方（`3bf3192e4d`） | v1.3.5 已做发消息自动取消归档，先核对 Harmony 是否需要同类撤销入口，再决定文案与位置 |

## 独立规划或不迁移

- 伙伴、群聊、Orca 协同、伙伴自动化、PR / 插件卡片与远程画面：Harmony 尚没有这些完整入口，
  不因 Mobile 修复而只移植局部组件。
- Agent Net 独立中转、加密媒体传输与共享任务附件：这是新传输体系；Harmony 当前官方 Device Link
  没有因此出现必须立刻调整的证据。若将来纳入，需要单独评估身份、协议、媒体和回退边界。
- iOS 实时活动、Android 通知和原生网络模块、Expo / Metro、分屏抽屉拖拽与新触觉反馈：
  属平台实现。鸿蒙只按同等用户体验评估，不复制原生代码或假定设备具备对应硬件。
- 视频流播放与相册视频附件仍超出 Harmony 当前一期范围，先保留为独立产品选择。

本次是源码评估，未运行 Harmony 新分支的 Local Test、构建或设备交互；上述「仅验证」项
不能写成已通过。
