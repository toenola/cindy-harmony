# Harmony v1.3.6 开发计划

> 状态：四项功能源码完成并安装手机，待交互验收；2026-11-15

仅在 `apps/harmony` 实现与验证。Mobile 与共享源码是用户可见语义的事实源；
鸿蒙采用 ArkTS / ArkUI 等价实现。

## 已实现范围

1. **异步提问**：先实现按请求保留草稿、撤回后补充发送和去重；覆盖多张提问并发、
   答案已在其他设备提交、回执丢失及 Host 撤回四种状态。不能仅凭 pending 缺席就重发。
2. **项目迁移**：在任务菜单接入被控端能力探测和移动；移动中锁住重复操作，
   成功后刷新权威任务快照，旧 Host、运行中与工作目录已删除均要有稳定结果。
3. **远程模型记忆**：将 v1.3.5 页面内的 effort / Fast 记忆扩成账号隔离的本地持久偏好；
   当前电脑和远程电脑、同名来源、恢复推荐及能力撤回分别验证。
4. **Issue 确认卡**：只对 `remoteConfirmSupported` 且当前用户可处理的请求提供远程确认；
   草稿保留、确认回执和共享访客边界与 Mobile 一致。
5. **针对性回归**：提问卡键盘遮挡、IM 附件来源、预览错误码、归档提示及搜索标签仍待设备与真实样本核对；
   未在本次四项功能范围内修改。

## 交付门槛

- 每项用户可见行为先对照 `apps/mobile` 和共享源文件，再改 Harmony；双主题 UI 使用现有语义 token。
- 在 `apps/harmony` 内运行相关 Local Test 与签名构建；有设备时只用 `entry-default-signed.hap`
  覆盖安装并验证真实交互。当前已覆盖安装并启动，尚未验收真实交互。
- 不在版本资料或提交中包含本机签名配置、证书路径或凭据；对合并后的完整 Harmony diff 做检查。
