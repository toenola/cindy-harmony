# Harmony 版本开发资料

本目录按版本保存 HarmonyOS 客户端的开发计划和技术资料。版本目录只描述
`apps/harmony` 的交付；Mobile、Desktop、共享 packages 和服务端仍由各自目录及规则约束。

## 目录约定

```text
version/
├── README.md
└── v<major>.<minor>.<patch>/
    ├── README.md
    ├── 开发计划.md
    ├── Mobile差异评估.md
    └── 技术设计.md
```

每个版本至少应包含：

1. `README.md`：版本状态、基线、分支、范围和资料索引。
2. `开发计划.md`：阶段、依赖、交付物、完成定义和验收门禁。
3. 与本版风险匹配的技术资料，例如差异评估、状态机、协议兼容和回滚说明。

## 维护规则

- 用户可见行为以 Mobile / 共享实现为事实源，HarmonyOS 使用 ArkUI 原生呈现。
- 计划必须区分“直接跟进”“鸿蒙等价实现”“仅验证不改运行时代码”和“明确排除”。
- 版本状态使用：`规划中`、`开发中`、`候选发布`、`已发布`、`已归档`。
- 开发中持续更新完成状态、决策和风险；发布后不覆盖历史结论，只补勘误。
- 技术入口必须指向当前真实源码；协议来源变化后同步修订，不保留失效路径。
- 发布前同步 `AppScope/app.json5` 的 `versionName` / `versionCode` 与
  `entry/src/main/ets/AppConfig.ets` 的 `appVersion`。
- 不在版本资料中保存签名路径、证书、密钥、Token、设备标识、构建产物或本机绝对路径。
