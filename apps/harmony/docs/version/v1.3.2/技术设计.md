> 日期：2026-10-12；仅描述 Harmony 控制端实现，不修改 Host、Mobile 或共享协议。

## 2. 默认模型与确认

- 新任务先读 Host 默认值；当前页面的显式选择优先，读取与回写按账号、设备、Agent、
  页面代次隔离。模型没有落定前不创建远端任务。关闭来源的判定区分显式 provider 与默认来源。
- 旧 Host 拒绝默认偏好通道时回退目录默认，继续保留既有工作目录记忆。
- 确认回包 accepted:false 是终局拒绝，任何 pending 补证都不能覆盖它；只有传输异常才补证。
  补证快照的连接与推送代次在查询发出前重新取；查询期间二者变化则换新快照，最多 3 次，
  不沿用提交开始时的连接，避免断线重连后已生效的决定被误报为失败。
  旧 Host 空返回兼容为成功，拒绝时保留卡片、用户草稿与可重试错误。
- Ask User 只替换共享规则认定的逃生选项，不吞掉“其他任务”等实质答案。IM 来源独立于
  自动审批故障描述，避免重复前缀；来源支持本机复制。
- 额度等待只接受有限正数 resumeAt；取消不支持时按当前连接隐藏入口。
- Agent 位于另一台电脑时只读模型／Agent 路由，发送与权限确认仍可使用；被控电脑额度
  不再冒充 Agent 所在电脑额度。SSH 与 Orca 的切换入口继续遵循原限制。

## 3. 连接恢复：故障半径三问

1. **触发层级**：前台回归是本客户端生命周期变化；请求背压是一个被控 peer 的准入拥塞，
   历史 patch 不匹配是一个任务的读取投影失配。它们都不是整条 relay 连接故障。
2. **动作层级**：只保留尚未过当前握手墙钟截止时刻且无退避计时器的尝试；WebSocket open
   重新启动看门狗后使用新截止时刻。每个物理 peer 同时在途上限 12，其中后台最多 4，
   排队最多 128，后台排队最多 96，给用户操作留空间。出队重验取消、账号、连接与调用归属，
   控制通道豁免，已发送调用不重放；取消不能在真实 settle 前提前释放物理容量。
   BACKPRESSURE 只反馈“电脑繁忙”，不触发整连接重建。历史失配只补读当前任务最新页，
   不调用全资源重新订阅与恢复。
3. **多 peer 证据**：Local Test 覆盖 peer 关闭、作用域别名、共享容量及其他 peer 在途不受影响；
   真实“两个控制端共享同一 Host，其中一端静默”的拓扑仍待 API 26 设备联调，不以模拟单测
   代替此验收。实际弱网、挂起、切网及 relay 聚合背压同样待验证。

## 4. 历史读取与活动展示

- 首屏与分页请求启用 lazyDetails:true、workLines:true，沿用现有 Harmony 请求预算，
  不扩大字节窗口；不支持 history view 的旧 Host 仍走原历史路径。
- patch 仅在账号／连接／任务读取 lease、baseRevision、工作范围与 parentToolUseId 匹配时应用。
  读取期间发生新消息、patch 或 invalidation，不发布失效结果；同任务并发 invalidation
  合并，必要时尾随补读，不清空已有窗口。
- 延迟详情以真实消息 ID 为所有者；支持子代理 anchorClientId／parentToolUseId、关联工具 ID，
  不假定所有延迟正文都使用 history-work 前缀。收起时释放详情可见租约，迟到详情不能复活。
- 展开尚未拿到正文时继续展示 Host 活动行；拿到正文后使用既有工具／思考呈现。活动行消费
  Host descriptor，不重新分析截断工具输入。模型来自持久 summary，成果沿用文件预览／分享
  通道，过滤未就绪和被排除的成果。
- 运行态预览与节点展示签名包含历史可见状态。贴底 guard 保留触摸、分页和阅读历史保护：
  松手不等于回到底部，只有本来跟随最新且当前无手势／分页时才自动补滚。
- 中断、续跑与多 seal 的长轮次按共享分组语义折叠，原始消息、错误及最终回答的操作身份保留。

## 5. 展示层与投递判定

- goal_status／goal_setup 仅从 assistant 展示正文末尾剥离；原始消息不改写，普通 JSON、
  正文中的协议示例与非 assistant 内容不受影响。
- 来源只消费 Host 元数据，插件优先于来源任务；设备维度独立，只显示其他已知平台设备。
  查看者 ID 使用 Harmony 自己的 Device Link ID；实时设备名优先、空名回退快照、同名补短 ID。
  来源不作为权限依据，不进入分享图片。
- 来源设备目录独立保存所有平台的实时名字，不改变只展示可被控桌面设备的任务列表。
  只有完整设备快照已加载时才判断来源设备已移除；换账号清空目录并拒绝迟到旧快照。
- Orca 既有协调消息只补呈现，默认收起，展开状态按账号／设备／任务／消息隔离，不增加
  协同能力入口。已发送引用 chip 是短纯文本，保留可见组合字符，不改 Composer 或发送数据。
- 删除菜单不依赖可能迟到的本地运行状态锁死入口；Host 仍是删除能否执行的权威，保留
  页面生命周期、消息身份与操作互斥。失败如实反馈，不自行丢弃消息。
- 5a 查询仅携带当前账号、设备、任务自有 deliveryClientIds，最多 64 个、每个不超过 256 字符。
  只认 inputDeliveryVersion:1；accepted 证明持久接收，pending 只证明 Host 队列观察，
  removed 为终局移除。这三者均不重发；缺回执不是“未发出”的证明。unknown 只有在查询前后
  都没有本条投递在途、且回执显式给出时才记为“电脑确认未收到”：Host 先等队列快照落盘再查
  快照与历史，并按 clientId 对远程入队去重，所以可用原 clientId 手动重发；新一轮投递开始即
  作废该结论，本轮能证明未发出时恢复。
  只有本地传输能够证明尚未发送才允许自动重试，旧 Host 无版本保留既有安全未发出判据。
  迟到读取、账号／连接切换及取消与 ACK 竞态不能覆盖新投影或用户新草稿。
- 不安全的失败气泡提供只读“核对投递状态”，而不是一个点击后无效的重发按钮；安全重试
  再次通过 Store 判据。队列节点 key 包含回执状态与重试资格，投影变化后按钮及时刷新。
  空 Host 投影把本地尚未发送条目移入过渡层时，只能凭本地未发送证明恢复初次发送；
  不能把 CHANNEL_NOT_ALLOWED 或投递在途期间读到的 unknown 当作未发送证明。
- 历史已确认且没有队列、锁、失败、取消或在途引用的跟踪记录可回收；未确定记录保留，
  近期历史证据继续防止旧 ID 重发。关闭页面不丢掉仍未核实的发送事实。
- 本期没有新增发件箱落盘、重启接管、附件所有权迁移或持久队列清理；这些仍属于 5b。
