# Harmony v1.3.7 开发计划

> 状态：源码实现中；2026-11-15；范围由用户确认

仅在 `apps/harmony` 实现与验证。开发前按 [Mobile 差异评估](./Mobile差异评估.md) 中的源码入口核对最终行为。

1. **持久发件箱**：保存待确认发送的文本与附件引用；先持久化再派发。重启后先按 clientId 与远端队列／历史对账，不确定时让用户手动决定，不自动重发。账号切换、登出、取消及附件所有权须闭环。
2. **长历史离线缓存**：按账号、设备、任务隔离历史页，支持冷启动重进长任务；网络结果仍是权威。分页、断档、写盘失败和清理按 Mobile 最终语义实现，不能只放大现有最近窗口常量。
3. **模型账号额度**：在模型选择器里按来源／账号显示余量及重置时间；每个账号一次读取，不按模型行重复请求；未支持和失败不冒充零额度。
4. **附件与文件预览**：图像全屏查看与切换，SVG 文件图形预览，PDF 交系统阅读器；保留原文件来源与可读失败提示，不把预览失败当成消息发送失败。
5. **列表稳定**：复现会话／项目顺序分批到达的跳行；在账号、设备和筛选范围内保持已展示行的位置，主动排序、刷新完成和重新进入时重算。
6. **模型定位**：新建页和详情页打开模型选择器时定位当前行；远程目录晚到后允许有限补偿，用户滚动后停止自动定位；验证同名不同来源。

输入建议及本机开关留给后续版本。其余模型来源、公式、重复请求和弱网场景做针对性回归；只有确认缺口才改。

用户本轮指定先只改源码，暂不连接设备。当前工作环境未提供 `devecocli`、`hvigorw`、`hdc`，因此 Local Test、签名构建、Light / Dark 和真机交互仍待具备工具链的环境验证。恢复验证时只在 `apps/harmony` 内执行，并使用现有签名配置生成的 `entry-default-signed.hap` 覆盖安装；不得把本机签名配置、证书或密钥纳入提交。
