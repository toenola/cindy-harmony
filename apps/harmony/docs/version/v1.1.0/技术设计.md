# v1.1.0 技术设计

本文定义 v1.1.0 的核心实现边界。具体字段名和系统 API 在开发时以当前源码、Mobile
事实源和 `devecocli docs` 查询结果为准，不凭文档草图新增协议。

## 1. 消息投影正确性

### 1.1 轮次边界

消息投影必须先确定本轮用户边界，再把 plan / work group / task activity 归入该轮：

```text
上一条用户消息
  └─ 本轮 activity / plan / tool / assistant 正文
下一条用户消息
  └─ 新一轮，禁止被上一轮未完成 plan 吞并
```

实现落点：

- `entry/src/main/ets/core/messages/MessageRender.ets`
- `entry/src/test/LocalUnit.test.ets`

边界测试至少覆盖：旧 plan 未结束后出现新用户消息、子 Agent plan、同毫秒消息和计划终态。

### 1.2 时长锚点

完成态工作过程的开始时间优先使用本轮用户消息时间；只有缺少用户消息时才回退到首个
activity 时间。结束时间沿用权威终态时间，非法或逆序时间不显示负时长。

### 1.3 Pi 命令投影

内部命令值与用户展示分层：

```text
远端 / 存储 / 发送：/skill:git
界面 / 复制 / 编辑：/git
```

转换必须是纯函数，只处理确认过的 Pi Skill 前缀；普通 slash 命令和用户正文不得误改。

## 2. 任务级 Pi 与模型默认值

### 2.1 roster 绑定

- 已有任务调用 `maker:list-agent-commands`、`maker:list-agent-skills` 时传当前 `sessionId`。
- 新任务页只做创建前预览，保持不传 `sessionId`。
- 页面切换后到达的旧 roster 响应不得覆盖当前任务，可复用 session / generation 校验。

### 2.2 默认模型选择

`ComposerCatalog.ets` 负责把 provider、model 与 `newSessionDefault` 归一为明确候选：

1. 读取远端显式默认标记。
2. 对 Pi 接受 `pi`、`claude-code` 等已知身份标记。
3. 保留候选原始 provider 身份，不按显示名跨 provider 合并。
4. 远端默认不可用时才退回当前稳定默认值。
5. 用户手动选择始终优先，目录刷新不得无提示改回默认。

新建页和已有任务页共享同一套目录与投影，仅保留 session 绑定差异。

## 3. 消息 authority 与内存治理

### 3.1 authority fence

每次进入、离开、重新聚焦或切换任务都推进详情 authority generation。异步历史读取、
实时 push 和补拉结果提交前必须同时满足：

- deviceId 仍一致；
- sessionId 仍一致；
- generation 仍是当前代次；
- 当前详情仍持有该任务的可见或后台工作租约。

不满足时丢弃旧结果，不更新 UI、缓存窗口或当前订阅状态。

### 3.2 两类任务策略

自动化任务使用现有权威分类字段识别，禁止靠标题或本地字符串猜测：

| 类型 | 可见时 | 离开后 | 持久缓存 |
|---|---|---|---|
| 自动化任务 | 保留一个最新 80 行窗口 | 回收隐藏内容和渲染投影 | 不长期落盘 |
| 普通任务 | 保留当前窗口与必要工作态 | 压缩为尾窗，按全局预算竞争 | 保留现有最新 80 行快照 |

### 3.3 全局预算

- 普通任务消息缓存预算：约 64 MiB 且最多 800 行，以先达到者为准。
- 字节数使用稳定、可测试的近似估算，不在热路径反复 JSON 全量序列化。
- LRU 淘汰只释放内存对象；持久快照删除是独立决策，禁止绑定执行。
- 预算和单任务 80 行持久窗、现有 1600 行防御上限的关系在实现时收敛为一个入口，
  避免三套裁剪逻辑互相覆盖。

### 3.4 不可淘汰工作集

以下内容在对应租约结束前受保护：

- 本地系统卡；
- 乐观用户消息；
- 未收敛 assistant 流式消息；
- 当前草稿和待发送队列；
- Permission / Ask User / Plan Review；
- 上传中或可重试附件；
- 本地 send / stop / retry / resolve 工作。

保护结束后再进入普通 LRU，不允许通过内存治理清空新草稿或丢失可恢复操作。

## 4. Composer、滚动与标题

### 4.1 发送接管尾部

用户主动发送被本地接受后：

1. 设置 `followingLatest=true`；
2. 恢复默认尾部窗口；
3. 在乐观用户消息进入列表后滚到末尾；
4. 后续流式内容保持跟随，直到用户主动上翻。

失败前未被接受的发送不改变阅读位置；用户主动上翻仍是关闭跟随的唯一来源之一。

### 4.2 触控与模型信息

- 队列图标 + 文字按钮触控高度至少 44vp，但保持现有图标胶囊视觉密度。
- 模型元信息在窄屏可换行或分层，不横向挤出 Composer。
- icon-only 控件有可访问性名称；Light / Dark 使用成对语义 token。
- 复用现有官方悬浮 Composer 和按钮锚定弹层，不复制 React Native 布局。

### 4.3 附件首条标题

标题候选顺序：

1. 非空文本摘要；
2. 第一张图片的本地化短标题；
3. 第一份文件的安全显示名；
4. 现有新任务占位标题。

文件名必须去除路径，只使用展示名。preview 在取消、上传失败、创建失败、重试放弃和页面
离开时清理；远端权威标题一旦到达，立即覆盖本地 preview，之后不得反向覆盖。

## 5. Device Link 1013 拥塞状态

普通重连稳定性和拥塞恢复使用不同计时器：

```text
连接成功 ──连续稳定 10 秒──> 清普通重连退避
    │
    └────连续稳定 15 分钟────> 清 1013 拥塞 streak / cooldown
```

- 短暂连接成功不得清除 1013 历史。
- 新的 1013 在 15 分钟窗内继续累计并延长冷却。
- 正常关闭、鉴权失败和网络切换不伪装成 1013。
- 计时器在显式停止和对象销毁时释放，旧连接计时器不得影响新连接代次。

测试覆盖首次 1013、短成功后再次 1013、稳定 15 分钟后重置、非 1013 关闭和旧计时器竞态。

## 6. Harmony 原生会话分享图片

### 6.1 数据投影

分享只消费当前用户可见的稳定投影：

- 保留用户消息、assistant 正文和用户当前展开的工作内容。
- 折叠且不可见的正文不偷偷出现在分享图中。
- 交互按钮、发送队列、内部错误详情、路径和凭证不进入导出。
- 分享开始后内容仍可能更新；导出前冻结一次权威 snapshot，避免半新半旧。

### 6.2 资源就绪

- 品牌资源和必要图片就绪后再开始生成。
- 附件图片解码失败时保留可读占位，不阻塞整个分享。
- 分享任务结束、取消或页面销毁后释放 PixelMap、临时文件和监听器。
- 临时文件放应用缓存目录，通过系统分享 URI 交接，不写入仓库或长期用户数据目录。

### 6.3 长内容

2026-08-20 已通过 DevEco CLI 1.2.0 的官方文档索引确认
`@ohos.arkui.componentSnapshot` / `ComponentSnapshot` 支持把已加载或未加载组件树生成
PixelMap。

2026-08-23 补充核验（本机 DevEco SDK，API 26）：

- `@ohos.arkui.componentSnapshot.d.ts` 与 `@hms.collaboration.systemShare.d.ts`
  均存在于当前 SDK，分享面板可用（Share Kit 仅 Stage 模型）。
- **像素上限有硬约束**：截图受 GPU 最大纹理尺寸限制，超限返回错误码 `100001`。
  常见值为 `width: 8192 height: 8192`，可用
  `hdc shell hidumper -s 10 -a 'vktextureLimit'` 查询当前设备实际值。
- 官方对长内容的建议实现是**滚动截图后自行拼接**（见「截取长内容（滚动截图）」与
  「长截图」最佳实践），与本计划禁止无上限画布的要求一致。

因此本版按以下决策实现：优先通过 API 26 `getSizeLimitation()` 读取当前设备组件截图
宽高上限，并与 8192px 保守上限取较小值后留安全余量。导出前使用
`MeasureUtils.measureTextSize()` 按分享画布同款字体、行高、内容宽度与内边距测量每张
内容卡，再按真实测量高度顺序分段；builder 根节点固定宽度、限制最大高度并裁剪越界
绘制，作为测量误差下的最后防线。单卡自身仍超过上限时明确提示缩小范围，禁止静默
丢正文。分享预览与最终文件必须一致，取消后不残留临时资源。

## 7. 平台等价交付

### 7.1 beta / release

- 定义 Harmony beta 与 release 的构建身份和分发资料，不引入 Expo OTA。
- `versionName`、`versionCode`、`AppConfig.appVersion`、设置页展示和 Device Link 上报一致。
- 不修改或复制本机签名块；beta / release 都使用用户现有可用签名流程。
- 若现有更新服务支持 Harmony，则复用其 channel 契约；否则把服务端 / 分发平台接入列为
  外部依赖，客户端不得假造已可 OTA。

### 7.2 可选安全观测身份

在 `core/` 定义最小 adapter，由登录生命周期调用：

- `bindUser(userId)`：登录完成后执行；
- `clearUser()`：登出开始即执行；
- 默认实现为安全 no-op；真实 SDK 实现按区域和构建配置注入。

adapter 不持久化 userId、不输出日志，失败不阻断认证。引入厂商 SDK、权限或配置前必须
补隐私和凭证评审，并验证冷启动、崩溃归因、换号和强杀后的归属不会串号。

### 7.3 DevEco 和系统选图器

- 所有文档检索、构建、设备选择和运行操作遵循 DevEco CLI Skill 与开发指南。
- 运行前核对当前工程、设备 ID 和 signed HAP 路径；只覆盖安装。
- PhotoViewPicker 验证只读用户选择的 URI；URI 过期时支持重新选择，不扩大权限。

## 8. 回滚边界

- 消息内存治理、Device Link 冷却、分享导出和观测 SDK adapter 分为独立提交，便于逐项回滚。
- 不通过删除持久缓存、清应用数据或卸载应用回滚。
- 新策略出现风险时可回退到 v1.0.0 的单任务缓存和重连行为，但不得回退已修复的消息轮次
  归属或造成草稿、队列、交互、上传工作丢失。
- 任何协议变化必须保持旧 Desktop / 旧 Harmony 的可降级兼容。
