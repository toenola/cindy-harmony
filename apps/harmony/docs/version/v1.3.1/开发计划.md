# Harmony v1.3.1 开发计划

> 状态：候选发布（待 API 26 设备验收）
>
> 范围确认：2026-09-10
>
> 开发分支：`feat/v1.3.1`；上游基线：`abcf92c2b`

本期纳入四项改动，按以下顺序推进。行为依据和现状见 [Mobile差异评估](./Mobile差异评估.md)。实现与本地自动化已完成；未勾选项为设备联调验收，详见 [验证记录](./验证记录.md)。

## 一、历史按需加载、流式正文交接与弱网恢复

直接跟进 Mobile 的历史读取和恢复语义，在鸿蒙现有缓存、订阅和补齐逻辑上实现。

- [x] 接入按可见内容分页的历史视图；折叠工作组读取摘要，展开后按需读取详情。
- [x] 请求前协商 Host 能力；旧 Host 回退原始消息分页，连接失败不能误判为能力不支持。
- [x] 流式正文保留到权威历史接管，保证完成时正文不丢失、不重复、不乱序。
- [x] 合并同设备、同任务、同连接代次、同窗口语义的重复读取；迟到响应不得覆盖新推送。
- [x] 各项读取独立发布结果和重试，避免单项失败重放整批请求；离线时保留已有可读内容。
- [x] 完成重新进入任务、前后台/网络切换和上翻期间的恢复路径；生命周期自动化通过，真实设备场景待验收。

交付物：历史视图适配、恢复逻辑及对应单测；补充新旧 Host 兼容和恢复状态说明，并回答远程适配规则中的“故障半径三问”。

验收：新旧 Host 均能读取完整历史；工作详情按需加载；弱网重连后正文与队列收敛；上翻阅读时不被强制拉回底部；旧响应不能污染新连接或其他设备的数据。

## 二、模型供应商来源与小上下文切换保护

直接跟进 Mobile 的供应商路由语义；选择器与确认交互使用鸿蒙原生实现。

- [x] 对齐同一供应商多个账号来源的标识、分组、默认来源及实际选中来源。
- [x] 现有任务保留当前实际使用但已停用的来源选中行；新任务和新路由禁止选用停用来源。
- [x] 保持用户模型显示开关、付费限制和当前选中行规则；目录加载未就绪时不错误覆盖选择。
- [x] 切换较小上下文模型时，已知用量达到本地目标窗口须确认；SSH 用量达到目标窗口 90% 时阻止切换；未知值沿用 Mobile 的放行语义。
- [x] 新建与已有任务共用目录解析和选择规则，保留实际运行模型与待生效选择的区别。

交付物：供应商目录适配、选择器状态和窗口保护，以及来源/阈值边界单测。

验收：同名模型的不同账号来源不串用；停用来源显示与真实运行来源一致；取消切换保持原选择；本地窗口边界、SSH 90% 边界及未知数据行为与 Mobile 一致。

## 三、新建任务目录记忆与同名电脑、项目标注

直接跟进 Mobile 的偏好和身份规则，在现有本地新任务草稿与项目列表上补齐。

- [x] 记住新建任务上次选择的项目/对话类型。
- [x] 按账号和设备保存最后显式选择的项目目录，重新进入时优先恢复；目录字符串原样保存。
- [x] 连续修改偏好按顺序持久化，账号切换后不恢复其他账号目录。
- [x] 全设备视图展示项目所属电脑；同名电脑通过设备 ID 消歧，并体现离线状态。
- [x] 已选定单设备时避免重复机器标注，同时保留项目识别信息。

交付物：新建偏好存储、项目身份展示和偏好/消歧单测。

验收：退出重进和重启后恢复正确选择；不同电脑与账号互不覆盖；同名电脑下同名项目可区分；偏好恢复不覆盖正在编辑的草稿。

## 四、附件连续性、长历史滚动、草稿恢复与配额展示

现有附件、滚动和草稿能力先按场景验证，存在差异时补齐；配额与用量摘要采用鸿蒙等价实现。

- [x] 待发送、排队和正式消息交接时保持附件布局与预览连续，正式媒体接管前保留本地预览。
- [ ] 验证长历史上翻、补页、流式生成和发送新消息时的锚点与分组稳定；修复闪图、跳高和滚动抢占。
- [ ] 验证中文组合输入、收起再展开、后台返回后的编辑与草稿恢复；队列变化和发送确认不得清空新草稿。
- [x] 在任务菜单展示实际供应商来源对应的配额与用量摘要，正确处理更新时间、币种和不可用状态。
- [x] 区分上下文 tokens、账户配额与任务用量，不把账户总量当作单个任务消耗。

交付物：配额/用量投影与菜单展示、现有交互的回归记录及必要修复；投影逻辑补单测。

验收：附件交接不闪烁或丢预览；阅读位置稳定；返回后能继续编辑且草稿完整；额度与实际来源一致，不可用数据不伪装成零额度。

## 执行依赖与交付门禁

第一项先稳定消息数据和恢复，再完成依赖这些状态的第四项滚动、附件回归；第二项先确认供应商来源，再接第四项配额读取。第三项可独立实现。

- [x] 实现前读取各项触发的协议兼容、远程适配、模型目录、凭证与存储、媒体、配置和设计专项规则；对涉及数据安全的改动先说明风险。
- [x] 仅在 `apps/harmony` 修改与验证；遵循 Mobile 行为语义，ArkUI 原生呈现，不移植 RN/WebView 专属补丁。
- [x] 新增 UI 使用 Light/Dark 语义颜色，并补齐五种语言资源。
- [ ] 完成窄屏、展开横屏、双主题和关键交互的实机目检。
- [x] Harmony Local Test 与 `devecocli build` 通过，使用现有签名生成 `entry-default-signed.hap`。
- [ ] 在 API 26+ 环境覆盖安装 signed HAP；签名异常按开发指南停止处理。
- [x] 完成 Harmony 差异检查，记录新旧 Host、弱网、设备与主题验证范围。
- [x] 发布准备时同步应用配置和上报版本为 1.3.1；提交保留 DCO 签名，推送与发布遵循用户授权。

## 本期范围边界

本期的多账号供应商适配是被控电脑的模型账号来源，不包含 Cindy 登录多账号切换。登录多账号、伙伴、远程桌面和完整语音听写仍独立规划；完整历史磁盘缓存扩建、模型折扣展示与本地诊断上传不自动纳入本期。
