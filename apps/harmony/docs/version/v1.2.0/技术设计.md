# Harmony v1.2.0 技术设计

## 1. 模块边界

| 模块 | 主要入口 | 责任 |
|---|---|---|
| 任务搜索 | `entry/src/main/ets/core/tasks/TaskSearchStore.ets`、`pages/TaskListPage.ets` | 远端搜索、旧端/缓存回退、设备与页面上下文、结果打开 |
| 项目顺序 | `core/tasks/TaskProjectOrderStore.ets`、`pages/TaskListPage.ets` | host 正本读写、owner stamp、路径归一化、可见项重排 |
| 消息分享 | `core/sharing/ShareSelectionStore.ets`、`pages/TaskPage.ets` | 稳定 ID 选择、可见性过滤、冻结投影、预览和资源释放 |
| 生成状态 | `core/messages/GenerationStatus.ets`、`core/messages/MessageStore.ets` | 指标解析、turn 边界、可靠性降级和 UI 投影 |
| 队列与恢复 | `core/messages/InputQueueStore.ets`、`MessageStore.ets`、`AppServices.ets` | 远端证据、single-flight、连接/请求代次和独立重试 |
| Composer 草稿 | `core/messages/ComposerDraftStore.ets`、`pages/TaskPage.ets` | `deviceId + sessionId` 隔离、旧键一次性迁移和异步写入围栏 |
| Subagent | `core/messages/AgentTaskStore.ets`、`SubagentDetailPresentation.ets`、`MessageRender.ets` | 持久终态、历史合并、实时树和只读详情 |

## 2. 权威与代次不变量

1. Desktop 是任务、消息、项目顺序和输入队列的权威来源；本地乐观状态在没有远端证据时只能显示为过渡态。
2. 异步结果落地前必须通过对应的 device/session/page/connection/owner fence；页面离开、设备切换或断线会推进代次。
3. 同一设备或任务的恢复操作采用 single-flight；重复 presence、link-open、列表和消息补拉不能并发制造相互覆盖的快照。
4. 断线恢复中的旧 Promise 不一定能取消，但恢复代次变化后不得写入消息窗口、运行态或订阅 ACK。
5. 项目顺序只重排当前可见项，隐藏设备或筛选项保持原槽位；无同步 channel 时保留本机展示，不污染 Desktop 正本。
6. 已有任务的 Composer 草稿必须同时绑定远端 `deviceId` 与 `sessionId`；只有无设备的新建任务使用全局草稿键。旧版无设备草稿只能由首次读取它的设备原子认领一次。

## 3. 消息分享流程

```text
普通消息分享入口
  → 独立选择态（稳定 message ID）
  → 仅收集当前可见 user/assistant 消息
  → 生成前冻结投影与分段计划
  → 生成图片并预览同一批文件
  → 系统分享完成/取消/退后台
  → 统一释放临时文件、PixelMap、选择态和页面状态
```

流式会话或无选中项不得开始选择分享；折叠工作过程、长消息和隐藏内部信息沿用当前可见内容语义。

## 4. 测试与发布证据

- Local Test 入口：`entry/src/test/LocalUnit.test.ets`，覆盖搜索、项目顺序、分享选择、生成指标、队列证据、恢复代次、Subagent 和交互降级。
- 构建入口：`devecocli build --product default --build-mode debug`，产物为 `entry-default-signed.hap`；只使用本机既有签名配置。
- 设备验证需要 API 26 设备，且必须完成覆盖安装、启动和关键交互；没有设备时只记录为未完成，不以 HAP 构建替代。
- 版本身份由 `AppScope/app.json5`、`AppConfig.ets` 和设置页共同校验，目标值为 v1.2.0 / `1020000`。
