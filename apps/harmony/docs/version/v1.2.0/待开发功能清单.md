# Harmony v1.2.0 本期待开发功能清单

> 状态：候选发布（代码开发完成，待设备/UI验收）
>
> 生成时间：2026-08-25
>
> 开发分支：`feat/v1.2.0`
>
> 对照范围：当前 Harmony v1.1.0 能力与最新原版 Cindy Mobile、Desktop、Device Link

## 1. 本期目标

本期优先跟进会直接影响鸿蒙端远程任务查找、跨端列表一致性、会话分享和运行状态真实性
的功能。实现时遵循以下边界：

- 用户可见行为以 Mobile 和共享实现为事实源，ArkTS 只做 HarmonyOS 等价实现。
- Desktop 继续作为任务、消息、项目顺序和输入队列的权威来源；本地缓存不能自证成功。
- 只修改和验证 `apps/harmony`。需要共享协议或 Desktop 配合的事项先登记依赖，不在本仓
  私造平行协议。
- 新增 UI 同时适配窄屏、展开横屏、Light、Dark、字体放大和减弱动态效果。
- 不覆盖或提交本机 `build-profile.json5` 签名配置。

## 2. 第一批：核心用户功能

### 2.1 远程权威任务搜索

目标：搜索结果不再局限于当前已经加载到鸿蒙内存中的任务。

- [x] 接入 Desktop `local-db:conversations:search`，按可用设备并发搜索。
- [x] 支持搜索任务标题和完整消息正文。
- [x] 支持按设备、项目目录、Agent、任务状态和最近活动筛选。
- [x] 合并多设备结果并去重，明确展示结果所属设备和项目。
- [x] 支持打开未出现在当前任务列表快照中的历史任务。
- [x] Desktop 离线或旧版本缺少 channel 时，安全降级到当前本地缓存搜索。
- [x] 搜索请求增加防抖、请求代次和页面离开 fence，晚到结果不能覆盖新查询。
- [x] 窄屏和展开横屏共用同一搜索语义；从结果进入详情后保持正确设备与任务上下文。

验收结果：能够通过历史消息正文找到旧任务；跨设备结果不会串设备；旧 Desktop 上仍可
使用本地搜索且不会显示虚假“完整结果”。

### 2.2 项目顺序跨端同步

目标：Desktop、Mobile 和 Harmony 对同一设备的自定义项目顺序保持一致。

- [x] 增加“最近活动 / 自定义顺序”展示语义，并提供明确的项目拖动入口。
- [x] 接入 `sidebar-settings:get-project-order` 获取权威顺序。
- [x] 接入 `sidebar-settings:apply-project-order` 提交拖动结果。
- [x] 消费 `sidebar-settings:project-order-changed`，实时响应其它控制端的修改。
- [x] 对齐 owner stamp、generation、水印和晚到响应 fence，禁止只同步一个裸数组。
- [x] 对齐 Windows、POSIX、worktree 项目键归一化规则，避免同一项目重复或错位。
- [x] 只重排当前可见项目时保留其它设备、其它筛选条件下的不可见项目位置。
- [x] 旧 Desktop 缺少同步 channel 时静默保留本机展示，不反复报错或污染远端顺序。

验收结果：任一端拖动项目后其它已连接端及时收敛；断线重连、主机重启和快速连续拖动
不会被旧顺序反向覆盖。

### 2.3 分享时选择消息范围

目标：用户可以选择本次要分享的消息，而不是只能导出全部可见会话。

- [x] 从会话分享入口进入独立选择模式，不影响普通消息点击、长按复制和滚动。
- [x] 支持逐条勾选，点击消息行可切换选中状态。
- [x] 提供已选数量、全选、清空、取消和分享操作。
- [x] 没有选中消息时禁用分享；流式消息未稳定时不得生成内容前后不一致的文件。
- [x] 生成前冻结所选消息投影，继续复用现有分段、预览、多图和系统分享链路。
- [x] 折叠工作过程、长用户消息和隐藏内部信息继续遵循当前可见内容语义。
- [x] 选择模式退出、页面销毁或 App 退后台后清理选择态和分享临时资源。

验收结果：可只分享任意几条用户或 AI 消息；选择操作不抢占滚动手势；预览与最终分享
文件的范围和顺序完全一致。

### 2.4 运行中生成速度

目标：任务运行时展示与原版 Mobile 一致的生成速率或累计用量。

- [x] 解析 status 事件中的 `outputTokens`、`generationDurationMs`、
  `generationActive` 和 `generationReliable`。
- [x] 数据可靠且生成进行中时显示 `tok/s`；只有累计用量时显示累计 token；无数据时
  只显示现有运行状态或时长。
- [x] 新 turn、重试、continuation、完成、关闭和断线恢复时正确清理上一轮速率。
- [x] 工具调用和 Subagent 区间遵循上游可靠性标记，不自行用墙钟时间推算虚假速度。
- [x] 为展示文本补齐无障碍说明，并确保窄屏和字体放大时不挤压停止按钮。

验收结果：运行中速度稳定更新；工具调用、重连和下一轮开始时不闪现上一轮旧数据；
不可靠数据只降级展示，不伪造速率。

## 3. 第二批：状态真实性与弱网可靠性

### 3.1 输入队列远端证据收敛

- [x] 对照 Mobile 最新实现，为每个任务记录远端输入投影代次和已出现过的 `clientId` 证据。
- [x] enqueue 回包丢失时，仅在 projection push、权威补拉或正式消息命中同一 `clientId`
  后认定已接收。
- [x] 没有远端证据时撤销乐观入队并恢复唯一一份可重试消息，不留下永久“同步中”气泡。
- [x] 已被 Desktop 快速取出进入 active turn 的消息不能被错误重发或生成重复任务。
- [x] 覆盖安全未发出、ACK 丢失、补拉失败、快速出队、断线恢复和用户手动重试。

### 3.2 Device Link 恢复与快照防重

- [x] 对照原版最新恢复逻辑核对当前 ArkTS 实现，只移植缺失语义，不另造第二套状态机。
- [x] 同一设备 / 任务的恢复快照采用 single-flight，重复 presence 和 link-open 不并发补拉。
- [x] sessions 列表、当前任务消息和输入投影分别重试，单项失败不拖垮其它恢复项。
- [x] 重连后重新建立必要 topic；晚到旧连接事件不得写入新连接代次。
- [x] 断线恢复后消息不重复、pending interaction 不误清、任务运行态不误报中断。
- [x] 项目顺序和远程搜索引入后沿用同一连接代次与 owner fence。

### 3.3 Subagent 历史终态

- [x] 读取持久消息上的 `agentTaskStatus`，优先恢复 `completed`、`failed`、`stopped` 终态。
- [x] 历史回放不再只依据结果文本推断完成状态。
- [x] 完整消息与裁剪消息合并时保留更新、更权威的终态元数据。
- [x] live `agent_task_update` 与持久终态使用同一展示模型，重进任务不把失败任务显示为运行中。

### 3.4 电脑端专属确认状态补齐

- [x] 保留现有 `issue_confirm`、`plugin_setup` 和未知交互的只读展示语义。
- [x] 补齐 `rename_sessions_confirm`、`ghost_grant_confirm` 等最新类型的明确标题和说明。
- [x] 只能在 Desktop 完成的交互不得错误接管或永久禁用 Harmony Composer。
- [x] `plugin_setup` 只在共享语义允许时提供取消，terminal 状态不展示无效操作。
- [x] 未识别新类型继续安全降级为只读卡，并展示回电脑端处理的明确引导。

验收结果：弱网恢复后没有重复消息、幽灵队列项或错误运行态；历史 Subagent 和电脑端专属
确认卡展示真实状态，同时不阻塞用户继续查看会话。

## 4. 后续能力：Subagent 子对话详情与控制

该项排在核心功能和可靠性收口之后，是否进入 v1.2.0 候选版本由前两批进度决定。

- [x] 点击 Subagent 工作组可进入完整子对话详情，而不只显示摘要卡。
- [x] 展示父子层级、状态、耗时、消息正文、工具过程和最终结果。
- [x] 历史恢复与实时更新共用同一子对话模型。
- [x] 仅接入共享协议已经支持的停止或控制动作；没有权威能力时只读展示，不伪造按钮。
- [x] 返回父任务后保持原消息滚动位置和工作组展开状态。

## 5. 已覆盖能力：只做回归，不重复开发

- [ ] 历史消息头部加载后保持当前阅读位置。
- [ ] 用户发送成功后回到底部并继续跟随流式回复。
- [ ] 用户正式消息、图片消息和排队消息统一靠右，AI 回复靠左。
- [ ] 排队序号、发送中、失败、删除、重试和草稿保护实时刷新。
- [ ] Markdown、长文本跨行选择、复制、生成文件预览和系统分享保持可用。
- [ ] 工作过程、计划卡、思考文本和 Subagent 摘要继续实时刷新。
- [ ] 会话标题栏 Git 分支、紧凑菜单、双栏顶部材质和可拖动分隔线不回退。
- [ ] 新建任务和已有任务 Composer、模型选择器、权限模式、附件及键盘避让保持一致。
- [ ] 任务置顶、归档、恢复、重命名、滑动按钮和底部导航收起行为保持可用。

## 6. 本期明确不移植

以下能力属于 Desktop 或其它平台的本机管理与工具链，不进入 Harmony Core：

- Desktop Ollama 安装、模型下载和本地运行时管理。
- 插件 Library、插件发布、Broker / OIDC 和市场管理界面。
- Desktop Usage History 设置页、辅助模型配置和窗口行为。
- Linux 安装、Xbox 手柄和 macOS 专属视觉 / 全屏恢复。
- Expo OTA、Mobile 语音词典、Metro takeover 和原生 WebView 分享实验。

本地模型如果已经由 Desktop 通过现有 provider / model RPC 暴露，Harmony 只需确保模型
列表和发送参数兼容，不负责在设备上安装或管理 Ollama。`thinkingEnabled` 暂不增加独立 UI，
待原版 Mobile 正式提供同类入口或产品另行裁决后再跟进。

## 7. 国际化与发布范围

- [x] 本期所有新增文案使用仓库术语表和 i18n 资源，不继续扩大硬编码中文范围。
- [ ] 如果 v1.2.0 作为 Global 版本交付，另立既有 Harmony 文案国际化清理项并完成目标语言
  矩阵；不能把“新增文案已国际化”当成整个应用已完成多语言。
- [x] Light / Dark 复用语义 token；未完成的实机模式验证必须如实登记。

## 8. 推荐开发顺序

1. 远程权威任务搜索。
2. 项目顺序跨端同步。
3. 分享消息范围选择。
4. 运行中生成速度。
5. 输入队列远端证据、Device Link 恢复和 Subagent 历史终态。
6. 最新电脑端专属确认类型。
7. 评估是否在本期加入完整 Subagent 子对话详情。
8. 执行已有能力回归、版本身份同步和候选发布验证。
