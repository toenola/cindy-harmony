## 已知边界与验收限制

- 当前电脑路由 API 没有鸿蒙专用的后续引擎过滤参数。本次显式选路遇到 ACP 会拒绝；不能保证电脑持续托管在将来回合绝不会提出 ACP。客户端不新增不兼容 wire，也不静默改写电脑决策。
- 原 `learn:start` 没有可核验的幂等重放入口。真实 runId 返回才完成分享内容消费；回执未知时保留命令意图并让用户查看原任务，不依据普通输入发件箱不存在重执行。
- 系统 ShareKit 未提供已核验的跨启动统一投递 ID。同 Want 重回调和待处理相同内容可合并；已消费后全新 Want 的同内容可能是用户新分享，不能永久按内容去重。
- 复制文件成功、分享账本落盘前崩溃可能残留私有 UUID 暂存文件。正常消费、取消、到期按所有权清理；不无依据扫描删除可能仍被草稿引用的文件。
- 系统卡片只展示主应用已有授权快照；后台不单独拉取额度。过期、离线和真实零值分开显示。
- 真实系统 API、双账号授权、原生加密存储、网络互通、折叠/展开、大字体/键盘和 Light/Dark 尚未提供本版本的设备验收证据。不能将版本标为真机验收完成。

1. 使用现有签名包覆盖安装，确认账号、现有任务、草稿和自建中转配置保留。
2. 新建普通/路由任务，发送、断网恢复、同 ID 对账；确认普通发送没有被导入守卫阻断。
