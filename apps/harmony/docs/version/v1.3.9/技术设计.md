# v1.3.9 集成契约

> 状态：公共接线完成，设备验收待进行；2026-11-28。官方参考固定 `91179cedad`。本页记录实际公共接入边界，验证证据另见开发与验收记录。

## 所有权与生命周期

- Lead 维护公共页面、AppServices、连接客户端、原生入口、资源注册和测试注册。三个 Worker 共用当前检出目录，只写各自拥有的模块目录；不切分支、不提交或推送。
- 模块通过可注入的 transport/host 端口调用现有服务；页面不创建 HTTP/WebSocket。不新造全局 AuthStore、Device Link 实例或凭证副本。
- ownerKey 来自已登录账号；账号切换、登出、失权推进 generation。设备/群/资源/任务标识不能单独用作跨账号缓存键。
- 对同账号远控，目标电脑、实际 Agent 执行电脑、供应商来源分别传递。共享访客和云端群不伪装成同账号电脑。
- Store 必须提供释放订阅、取消定时器、使在途响应失效的生命周期接口；隐藏页面不继续发起可避免的读取。写操作使用官方幂等标识和权威回查，不在超时后生成新的业务 ID。
- 新能力先查宿主声明/响应；未知能力与临时失败分开，不能把空数组或零值当作所有错误的替代结果。

## 按模块隔离身份和通道

| 模块 | 身份/调用端口 | 集成方式 |
| --- | --- | --- |
| 智能路由 | 目标电脑上的现有 model-groups RPC；电脑决定实际来源 | 独立 Store/选择组件接入新建和任务页；解析、使用、提交是三个阶段 |
| 群聊 | chat-server 认证客户端，或电脑 remote-resource 投影 | 两种 adapter 共用原生展示；云端不建立假设备远控链 |
| 项目/资源 | 目标电脑 Device Link 的现有项目/资源 channel | 独立页面/面板接入列表，资料与目录归属不混用 |
| 共享任务 | 官方 scoped 或 Agent-Net 已有分享身份 | 成员资格/撤权与同账号控制分开；不自动改道当前自建中转 |
| 系统分享 | 鸿蒙系统 URI 授权→受控暂存→现有草稿/附件队列 | 先预览选择目标，用户明确发送后才写任务 |
| 用量卡片 | 本账号、指定电脑范围的现有只读快照 | 系统卡片读脱敏摘要；无账号 token、无厂商凭证、无常驻 WS |

各 Worker 首次回报必须列实际 channel、参数/响应、错误和能力判据，由 Lead 核对后登记；表中领域描述不是允许自行创造 API。

## 已核对：慢调用预算

权威来源为官方 `packages/device-link/src/allowlist.ts` 的 `INVOKE_TIMEOUT_OVERRIDES_MS`，Mobile 经公共 invoke policy 消费，不能只搜索 Mobile 页面寻找常量。

| channel | 执行/回包预算 | 原因 |
| --- | --- | --- |
| `maker:create-session` | 120 秒 | Agent 冷启动可能超过默认 30 秒；已有同 sessionId 创建回查保持不变 |
| `maker:compact-session` | 660 秒 | 电脑端 Pi 压缩可达 10 分钟，再留回程余量 |
| `maker:predict-prompt` | 45 秒 | 原有持久化、凭证刷新和建议生成链路 |
| 其他现用 channel | 沿默认或已有显式预算 | 不把慢操作预算扩成所有请求的统一超时 |

这些是请求预算，不是工期估计。不修改 wire、不自动重放写请求、不重启 peer。显式的调用方预算优先；本地排队仍最多 30 秒，避免慢操作积压隐藏后台读取。

故障半径：仅当前请求的等待时间变化；其他电脑、同电脑其他请求及全局心跳不重置；账号/连接代次校验与在途响应丢弃沿原生产链保留。需回归慢创建、取消、回执未知与旧请求失效。

## 已落地的生产接线

- `AppServices.modelRouting` 复用已有 owner invoke；新建页使用 prepare → 原创建/首输入 → 精确 accepted 后 finish，任务页使用原模型切换事务和 route note。权限、plan、effort、speed 按最终引擎能力处理，解析到 ACP 在明确发送前拒绝。
- `CloudChatRuntime` 使用官方 Chat Server、同一个 AuthStore 和私有存储；群目录/当前房间共用一个订阅实例。电脑群走独立的 remote-resource Store。两者分别校验云 actor 与实际电脑授权，不互换 roomId/deviceId。
- `SharedTaskRuntime` 按官方账号和认证代次隔离，独立于当前同账号控制中转。官方 scoped 和 Agent-Net 各自握手、link-accept、topic ACK、任务快照确认后才登记本地 canonical peer。主 wire 的物理 ID 上限保持 128，长 canonical ID 只来自可信注册表。
- 主中转断线只清 owner 请求/待发/消息信任；独立共享连接保留自己的调度、历史与持久发件箱。共享 ready 只恢复对应 peer，关闭只清对应交互和投影，不清其他任务。
- 共享附件通过注册的 guest 媒体端口上传、取回、删除。清理由成功上传时记住的当前路由授权；未知/撤权对象不得借 owner 路径删除。原 owner Agent-Net 删除不受影响。
- 电脑群媒体使用页面持有的 `OwnedHostMedia`，复用 `MessageStore.fetchRemoteMedia` 和原 presign/Agent-Net 下载。仅清理本页取件生成的临时对象；原上传引用不删除。账号/路由变化和离页关闭预览、使迟到结果失效。
- 被电脑群媒体租约清理过的对象不能复用电脑的旧上传缓存；实际取件透传现有 `skipCache`，可见队列仍负责去重与并发，不增加轮询。换主控制中转时精准撤销 owner 内存待发项，旧记录留在原磁盘作用域，独立 guest 队列保留。
- 项目目录选择、资料/图标保存、资源 schema 动作均进入既有电脑 channel；SSH 与本机目录身份不混淆。项目图标读取有后台并发预算。
- 系统分享通过 `systemShare.getSharedData` 接收，再经过私有暂存、预览、目标选择、独立草稿副本和原输入队列。用户发送前保留原 clientId 和文档快照；未知回执不会重分配 ID。
- 用量服务卡片只读已授权快照，不启动连接、不访问模型厂商。系统生命周期与主应用共用同步原子账本；同账号重启保留卡片范围，换账号/明确撤权清除旧数据。

### 恢复路径的故障边界

1. 单电脑/共享 peer 的失败只撤销该 peer 的请求、订阅 ACK、运行指标和问题卡；主中转恢复只补 owner，guest ready 只补自身。
2. 调度仍按实际物理电脑共享 12 路预算、后台 4 路及原排队上限；隔离不等于增加无限并发。读失败使用已有有界恢复，写失败不无条件重放。
3. 账号 epoch、主路由 generation、独立 guest identity、资源 lease 和精确文档快照分别校验。撤权、切账号和旧连接的迟到响应不能成为新会话或新草稿的事实。
