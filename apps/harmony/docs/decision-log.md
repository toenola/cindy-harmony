# Harmony 决策记录

本文保存 Harmony 的有意差异、理由和待办；偏离 Mobile、调整已裁决行为或核对剩余验收前阅读。历史条目保留，后续实现变化紧随原条目说明，不将历史状态当当前能力清单。

## D-001：采用独立 `apps/harmony`

- 日期：2026-08-04
- 状态：已决定
- 决策：Harmony 客户端放在 `apps/harmony`，不改造成 `apps/mobile` 的第三个平台。
- 原因：ArkUI + ArkTS 拥有独立 DevEco 工程、原生依赖、资源、构建和发布边界；避免影响 iOS / Android。

## D-002：采用 ArkUI + ArkTS

- 日期：2026-08-04
- 状态：已决定
- 决策：使用 ArkUI 原生 UI 和 ArkTS，不追求仓颉路线。
- 原因：稳定性、工具链和 ArkUI 集成优先；现有 Cindy 共享逻辑主要是 TypeScript，ArkTS 的迁移和理解成本更低。

## D-003：Harmony 端是远程控制端

- 日期：2026-08-04
- 状态：已决定
- 决策：Agent、工作目录、数据库、CLI、MCP 和插件继续运行在电脑端。
- 原因：一期目标是鸿蒙手机远程控制桌面 Cindy，不移植桌面执行环境。

## D-004：核心消息和 AI 交互一期完整实现

- 日期：2026-08-04
- 状态：已决定
- 决策：任务详情、历史消息、消息流、图片上传、Permission、Ask User、Plan Review 不做半套。
- 原因：历史消息包含结构化 Tool、Thinking、Todo、媒体和交互状态；事后补齐会导致历史数据无法可靠恢复。

## D-005：Device Link 不重新设计

- 日期：2026-08-04
- 状态：已决定
- 决策：Harmony 端实现平台适配和必要的 ArkTS Client，继续兼容当前 Device Link。
- 原因：保持桌面端和现有 Mobile 的互操作，避免维护第二套远程协议。

## D-006：ArkWeb 只用于复杂内容

- 日期：2026-08-04
- 状态：已决定
- 决策：整体 UI 使用 ArkUI；Mermaid、Math 和复杂 HTML/媒体内容可以局部使用 ArkWeb。
- 原因：既保持 Harmony 原生页面结构，又避免为复杂文档格式重复实现浏览器排版。

## D-007：第一期暂不做 Issue Confirm 手机提交

- 日期：2026-08-04
- 状态：沿用现有策略
- 决策：Harmony 端识别 `issue_confirm` 并提示回桌面处理，不提供 GitHub Issue 编辑和提交表单。
- 原因：它不是普通 AI 交互闭环；当前 Mobile 已采用相同的安全降级策略。

- 后续现状：该一期降级策略已被当前 `TaskPage.issueConfirmCard` / `issueDecision` 与 `InteractionStore` 的公开反馈预览、编辑、署名选择和显式确认实现取代（回归见 `V132Interactions.test.ets`）。仍由电脑端执行公开提交，手机不直连 GitHub；详见[交互确认](interaction-flows.md#5-issue_confirm)。

## D-008：空工程构建通过，暂不承诺真机验证

- 日期：2026-08-04
- 状态：部分完成
- 决策：DevEco 空工程的 `entry:assembleHap` 已构建成功；在模拟器或真机实际安装运行前，不宣称 Harmony 运行验证通过。

- 后续现状：空工程阶段已结束；各能力的安装 / 运行证据按对应版本和任务分别记录，不把早期构建结果当当前运行验收。

## D-009：开发顺序改为垂直切片

- 日期：2026-08-04
- 状态：已决定
- 决策：实施计划从「先完整基础层、后页面」改为「垂直切片」：每个切片以用户可见成果收尾（切片 1 是最小闭环：登录→设备发现→打开任务→发消息→收流式回复），页面与数据层同步开发。
- 原因：App 的渲染、滚动、流式合并等能力本质是页面的一部分，单测无法替代真机验证；按层推进会导致前期看不到成果、后期 UI 问题集中爆发。模块划分与 Store 架构保持不变，只重排交付顺序。
- 配套：早期切片计划已归档为历史组织方式；当前入口见[架构与代码地图](architecture.md)，交付条件见[验证清单](verification-plan.md)。

## D-010：任务列表滑动操作不支持全滑直达

- 日期：2026-08-11
- 状态：已决定
- 决策：Harmony 任务列表右滑和左滑只露出置顶 / 取消置顶、归档 / 恢复按钮；继续滑动并松手不得直接执行操作，用户必须点击按钮后才执行。
- 原因：全滑直达容易在浏览列表时误触，归档和置顶都需要明确的点击意图。该安全交互是 Harmony 相对当前 Mobile 实现的有意差异。

## D-011：富组件回答原生渲染的 Harmony 差异

- 日期：2026-10-22
- 状态：已决定
- 决策：`cindy-ui` 解析逐行移植共享 `richAnswer.ts`（上限、白名单、算术与可读文本一致），呈现用 ArkUI 原生组件；以下为有意差异：
  - `video` / `audio` 节点与 YouTube 链接降级为可点链接（YouTube 规范为 watch 链接），不内嵌站点播放器；`image` 复用正文 Markdown 图片链路。
  - JSON `null` 属性值按缺省处理（ArkTS 记录不承载 null），`patch` 传 `null` 不会清空该属性。
  - 折线图刻度不加千分位分隔符。
  - SVG 与折线图用 Canvas 绘制，资源色通过 `getOverrideResourceManager()` 按当前系统模式解析；深浅色切换由 EntryAbility 的配置通知与回前台同步写入 `cindyColorMode` 触发重绘。
- 原因：Harmony 没有安全的站点播放器嵌入链路（ArkWeb 仅用于复杂内容，见 D-006）；其余差异只影响边缘输入，不改变可读内容与交互语义。

## D-012：v1.3.3 消息呈现增量中无需移植的部分

- 日期：2026-10-22
- 状态：已决定
- 决策：
  - Harness 切换边界（#6260）不移植：Harmony 的待发送消息始终作为独立队列气泡排在全部历史之后，不像 Mobile 把乐观气泡插进历史，所以切换行不会被越过；回显后按 Host 落库时间排序，与 Mobile 测试夹具一致。
  - 跨电脑来源任务 `deviceId::sessionId` 不新增处理：Harmony 的来源任务标签本就只提供复制 ID、不跳转。
  - 失败采样折叠时，工作组身份只跳过失败采样正文，不改用共享的「首个非消息项」锚点，以保持 Harmony 已有工作组 key 稳定。
- 原因：上游修复针对的是 Harmony 不存在的实现路径；照搬只会引入无用代码或改变现有节点身份。

## D-013：厂商信息统一通过电脑端获取

- 日期：2026-10-22
- 状态：已决定
- 决策：Harmony 禁止直接调用模型厂商或 Agent 厂商接口获取信息；模型目录、能力、账户配额与用量、Agent 状态等统一经 Device Link 从电脑端读取。厂商通信、认证与缓存由电脑端负责，鸿蒙不持有厂商凭证，也不在电脑不可用时回退直连厂商。Cindy 自身的登录、设备互联和附件链路不受影响。
- 原因：用户明确要求区分鸿蒙直连与电脑端代查，不能把电脑端访问厂商也判成违规；原「账户配额与用量」本就经电脑端获取，用户确认恢复保留该入口，不因这一边界删除合规的电脑端能力。

## D-014：任务双栏改为按窗口尺寸判断

- 日期：2026-10-27
- 状态：代码已实现，待设备验收
- 决策：对齐 Mobile `sessionPaneLayout.ts` 的无折痕分支：窗口宽 ≥600、安全区宽 ≥760 且高 ≥480 时启用可拖动双栏，不再要求横屏和折叠展开态；列表宽 300 – min(420, 宽 − 400)，默认 min(320, 宽 × 34%)。宽窄切换继续保留当前任务详情。双栏下最近 3 个任务的消息列表常驻，隐藏列表暂停订阅、补页与贴底。
- 有意差异：Mobile 的列表最小宽度为 240vp；Harmony 标题栏需要同时容纳设备选择和四个操作入口，暂保留 300vp 下限，避免挤压或重叠，仍需在 Pura X Max 实测确认。
- 排队消息编辑：常驻任务被隐藏时与离页一致，取消未保存的编辑并释放远端编辑锁，恢复编辑前的草稿，避免这条消息在用户查看其他任务期间无法派发。保留编辑内容并在切回时重新加锁的方案暂不做。
- 不跟进：按折痕固定分栏、折痕避让与上下折键盘换区（鸿蒙拿不到折痕数据；用户主力机 Pura X Max 不使用半折姿态）。
- 原因：用户要求与官方折叠屏适配对齐。取代此前「仅展开横屏才双栏」的约定；阈值落地后需在 Pura X Max 各姿态实测校准。

## D-015：分屏单栏、双栏列表可收起与详情标题居中

- 日期：2026-10-27
- 状态：代码已实现，待设备验收
- 决策：
  - 系统分屏（`WindowStatusType.SPLIT_SCREEN`）与悬浮窗（`FLOATING`）时一律单栏，不再按尺寸判断。设备不支持窗口状态查询时按全屏处理。
  - 双栏时，会话详情标题栏最左侧提供收起 / 展开任务列表按钮（参考钉钉）。收起后列表只隐藏、不销毁，详情占满宽度；收起状态仅在本次页面生命周期内保持，退出双栏即恢复展开，不写入偏好。没有选中任务或正在新建任务时列表强制显示，避免困在没有列表的界面。
  - 会话内容区宽度上限放宽：消息流、交互卡片与错误提示 760→940vp，状态行与指令候选 736→916vp，Composer 720→900vp（只对会话详情生效，新建页不变）。展开屏收起列表后（约 1105vp）两侧留白由约 172vp 减半到约 82vp；聊天流按 DESIGN 属于铺满区域的内容，不受阅读宽度限制。
  - 会话详情标题在单栏与双栏下都居中：标题放得下时两侧按较宽的按钮组对称留白，严格对准中线；放不下时填满两组按钮之间的空间并以省略号截断。
- 原因：真机 Pura X Max 在用户的显示大小设置下（倍率 2.3375）竖屏宽 782vp、上下分屏约 782×540vp，按 Mobile 尺寸规则会在竖屏和分屏都进入双栏。用户接受竖屏双栏，但认为分屏双栏不合适，竖屏双栏偏挤时希望能一键收起列表。Mobile 双栏时列表常驻、没有收起入口，以上均为 Harmony 有意差异。

## 鸿蒙首页单独展示插件引擎额度

- 首页用量读取目标改为跟随 Mobile 的自动选择规则，不再跟随首页选中的电脑。

- 决策：用量面板保留现有桌面快照。打开或手动刷新时，仅对快照所选电脑、目录中声明可报告用量的插件引擎读取额度，成功且有数据时补充单独的额度行。
- 原因：Mobile 的插件额度位于会话菜单，Mobile 与 Desktop 的首页额度快照都不含插件行。鸿蒙首页是新增展示，复用既有插件用量契约，不改变快照、服务卡或桌面协议。

## 鸿蒙首页「+ → 新建伙伴」与 Mobile 的差异

- 决策：新建伙伴表单复用电脑端已提供给 Mobile 的 `teammates/bot/create` 资源（`maker:remote-resources:get` / `invoke`），名字、预置/上传头像、重名提示、失败重试（未确认结果复用同一 requestId）与 Mobile `CompanionCreateSheet` 一致。以下为有意差异：
  - 不做模型选择和「从其他 Agent 导入」：提交不带 modelChain，由电脑端按默认模型创建；电脑端报告没有可用默认模型时禁止提交并提示。
  - 可选电脑与「新建群聊」同口径（在线且可控制），不额外读取 manifest 判断 `open-create`；不支持的旧版电脑在表单里提示更新。
  - 成功后鸿蒙没有伙伴详情页：刷新该电脑伙伴列表，新伙伴带着主对话出现时打开它的对话；切换电脑范围、切换账号或 30 秒内未出现则放弃，不新增请求或轮询。
  - 上传头像取图片中心正方形（Mobile 由系统裁剪框裁切），其余尺寸与压缩规则相同。
- 原因：先以最小范围交付新建入口，不改协议、电脑端或 portable allowlist；模型选择器与导入流程体量较大，另行移植。


## 待办：用量快照中的插件引擎图标

- 用量快照的额度来源提供展示用的短名称、首字母、有限的内置品牌标记和来源 ID。来源 ID 可以指向普通供应商、账号或分享，但不保证能对应到插件目录中的引擎 ID。
- 鸿蒙沿用 Mobile 的名称与首字母徽标规则，不按名称、首字母或设备名认领插件来源。要显示插件自己的图标，需要电脑端在快照中提供图标或可关联插件目录的稳定身份，并按协议兼容规则评估新旧客户端互通。本次不改电脑端和协议。

## 鸿蒙首页「新建项目」「资源」入口位置与 Mobile 的差异

- 决策：首页列表顶部不再放文字按钮行。「新建项目」与 Mobile 一致，放在新建任务页项目选择器的末尾（保留原有「选择其他项目文件夹」）：电脑项目设置版本 ≥ 6 时打开现有新建项目面板，面板盖在草稿上方，草稿内容保持不变，建好后自动选中新项目；版本更旧或尚未读到时退回目录浏览。「资源」放在标题「所有任务」下拉菜单里，紧跟「所有任务」，是单一入口，打开当前选中电脑的现有资源面板；没有选电脑且不止一台可用电脑时提示先选择电脑。
- 与 Mobile 的差异：Mobile 在同一下拉中按电脑声明 `placement: 'home-scope'` 的远端集合逐项列出（伙伴集合除外），并跨电脑汇总打开（`homeChromeMenus.ts` 的 `buildHomeScopePullDownActions` / `openHomeRemoteCollection`）。鸿蒙只做单一「资源」入口，进入后由资源面板列出该电脑的集合。
- 原因：鸿蒙首页目前没有集合发现与跨电脑汇总能力，资源数据只在资源面板内按单台电脑读取；逐项列出需要新增首页层面的集合发现与汇总读取，本次先以现有面板保住入口，不新增请求。

## 鸿蒙工作目录浏览入口与同步

- 任务标题栏、任务详情的工作目录和任务内文件入口都指向同一工作目录浏览器。项目分组齿轮额外提供「浏览文件夹」，这是鸿蒙新增的独立入口，不选择任意一条任务代为浏览。标题下拉仍是当前根目录的路径层级，同 iOS。只有任务入口可以把目录或文件引用追加到该任务的输入草稿，不自动发送。
- 复用现有远程只读文件通道。打开、切目录或手动重新同步各读一次，排序和网格／列表切换在本地完成。前台文件页订阅该设备当前根目录，子目录切换不重订，后台或离开页面释放。只处理匹配设备、根目录和当前登录范围的文件事件，600ms 去抖，同一页面只允许一个目录读取在途，保留一次尾随刷新。不轮询目录。
- 故障半径仅限当前设备和目录。一次读取失败不视为共享连接失效，重连由已有链路处理，文件页只恢复订阅和目录读取。未确认订阅时不显示即时同步。返回前复核账号、设备和目录，旧页面或不同设备回包不得更新当前目录。不修改可靠层 ACK 或其它设备的连接。

### 文件预览与导出差异

- PDF 使用鸿蒙 SDK 26 的 PDFKit，在应用内从内存打开，不交给系统阅读器或写入本地文件。单文件导出走系统分享。用户发起导出时才探测能力，旧主机一次启动导出后串行查询状态，间隔至少 1 秒、等待最多 120 秒，页面失效后不再查询。已取得并消费的中转对象按原范围清理，取消前未取得对象键则由中转到期处理。
- HTML 在用户打开时构建内存资源快照，最多 24 个文件、4 MiB，不写本地缓存。只发现安全相对路径的文档和常见样式或媒体资源。ArkWeb 请求由专用 origin 的快照精确匹配，未命中统一返回 404，不放行网络或本地文件。与 Mobile 的动态 HTML 有差异：鸿蒙此模式不执行文档脚本。需要在真机确认网络封锁与本地拦截的顺序。
- Draw.io 使用与 Mobile 完全相同的离线 viewer，来自 Desktop 的 vendor 分发，Apache-2.0 许可证随包。固定渲染器脚本 3,807,539 字节，含许可证和两个薄入口共 3,820,241 字节。只允许包内渲染器和数据图片，文档 XML 作为数据传入，支持页签、图层和缩放。需真机验证多页和压缩文档。
- GLB／GLTF 由 Graphics3D Scene 和 Component3D 在端内渲染，拖动旋转，捏合缩放。先校验 GLB JSON chunk 或 GLTF JSON，再取同目录下最多 16 个纹理／缓冲文件，模型和依赖共 20 MiB。外部 URL、路径跳转和未认可的格式不交给原生解析器。资源只短期写进应用专用缓存目录，离开预览或失败后清理。需要真机确认 file URI、光照、不同坐标原点与编码的支持范围。
- 图片圈点按图像显示区域换算坐标，以原始像素尺寸离屏合成，结果作为当前任务的图片附件排队，不自动发送。项目独立入口没有任务归属，不显示圈点提交。源图取件上限 16 MiB／1600 万像素，托盘沿用既有附件预处理。
- 网格只在条目实质可见后读取缩略图，最多 2 个在途，按路径、修改时间与大小去重。图片用既有 thumbnail 操作，小于 24 KiB 的文档取文本片段，失败退回文件类型图标。排序与视图保存在本机 Preferences，键是账号／设备／工作目录的摘要，仅保存偏好值，不保存目录快照或文件内容。
- 鸿蒙现有任务结果和历史产物按钮复用文件夹路径入口。Mobile 的 CompanionTaskResultCard 以 childSessionId／workdir 绑定子任务，鸿蒙当前没有同款卡片或呈现模型；已有结果仅在可证明属于当前工作目录时进入文件夹，不从代理任务 ID 猜测子会话或其路径归属。

### 显示被忽略的目录

- 鸿蒙文件夹「…」对齐 Desktop，新增默认关闭的设备端全局偏好。只保存布尔覆盖，关闭时移除覆盖，不存路径。菜单复用已有文件能力探测，旧电脑禁用并提示更新。只在开启且支持时给当前目录的 `listDir` 发送 `showIgnoredDirs: true`，不使用完全绕过过滤的 `includeIgnored`。VCS 和系统垃圾继续不可见，名称与内容搜索契约不变。
- 现有远程 watch 不带展示偏好。被控端会过滤可放行目录内部的事件，在 `build` 等目录内需要使用「重新同步」读取最新内容。保持原订阅，无轮询、无协议调整，不把构建期间的高频变更转发给远端。

## 鸿蒙新建任务的 worktree 边界

- 沿用 Mobile 既有 Device Link 协议。鸿蒙仅在专用 facade 放行探测、分支列表、预创建、取消／回收、电脑默认值和三项 worktree 偏好读写，不扩通用模块入口或修改电脑端。
- 按设备与目录选择触发探测、读取默认值和分支偏好，点击分支才读列表。只有用户改变选择才写回，不轮询。非项目、非 Git、已在 worktree 内及不能按 recoveryKey 清理的旧电脑不产生预创建副作用。
- 先落盘同账号、线路和设备的恢复记录，再预创建，以同一任务 ID 和新目录创建会话，项目目录保持原路径。失败仅调用电脑端按 recoveryKey 取消或安全回收，依赖电脑校验未被会话认领。没有收到严格确认时保留本地记录，下一次同范围尝试时先补偿，不改走普通目录。

## 鸿蒙统一模型选择器收藏

- 模型收藏以被控电脑为准。专用调用入口只允许 `maker:model-favorites:get` 与 `maker:model-favorites:apply`，在连接前、发送前和收到结果后核对当前账号、线路和设备，不扩通用名单。
- 打开选择器和收到该电脑收藏变化时读取，不轮询。更新发送单条操作；取消收藏带旧记录作为 expected。远程电脑的模型收藏沿用 Mobile 的 providerId 位置编码，不把收藏键用作实际执行来源。
