## Design Context

### Users

Developers and knowledge workers use Cindy to delegate real work to agents on their own
computer, then inspect, continue, and correct that work from Desktop, Mobile, or Harmony.
The message view must make the agent's current result easy to scan while keeping detailed
thinking and tool activity available on demand.

### Brand Personality

Calm, precise, capable. The interface should build confidence during long-running work,
without turning implementation detail into visual noise.

### Aesthetic Direction

Radically minimal, near-monochrome, content-first. Use Cindy's semantic design tokens,
native platform layout, and both Light and Dark themes. The message hierarchy should match
Desktop and Mobile semantics; Harmony may use native controls but must not invent a second
message model.

### Design Principles

1. One turn of agent work reads as one compact work summary plus one final response.
2. Progressive disclosure: collapsed summaries stay quiet; details appear only on explicit tap.
3. User messages, work summaries, and assistant delivery content need distinct visual roles.
4. Behavior parity comes before platform-specific decoration.
5. Every visual change must work in both Light and Dark through semantic tokens.
